# 意味論リファレンス — 導出・検査・問い

koyu v0.12.0 現在。文法は [language.md](language.md)。ここに書くのは「書かれたものから何が導かれ、何が検査され、問いに何が返るか」— 形も数量も内外の別も、原本には無く、すべてここに定義される導出である。

## 1. モデル

合成後のモデルは次からなる: `spaces` (パス→空間: 型・レベル・矩形合併・areas・属性・出所)、`boundaries` (関係の列: a/b パス・kind・t/air/edge・openings・segs・出所)、`zones` (パス→集約)、`assets` (名→建具型)、`polygons` (パス→敷地形状)、`grid` / `levels`。出所 (`file`) は合成に参加したレイヤー名で、エラー・警告の位置表記 (`レイヤー:行`) に使われる。

## 2. 平面の導出

**共有辺。** 二つの空間の壁芯線分は、矩形合併同士の共有辺 (同一直線上で重なる区間) として導出される。共線の区間は一本にマージされるため、複数矩形をまたぐ開口も一つの線分上に置ける。

**外部境界。** 領域を持たない空間 (exterior等) との境界は、部屋の外周から「他の空間と接する区間」を除いた残りである。複数辺に分かれるため、開口を置くには `edge:` で辺を選ぶ。`edge` の方角は a側 (先に書いた空間) の矩形から見る。

**既定境界 (ADR-0014)。** 同一レベル (未特定同士を含む) で平面が接する領域つき空間の組に、宣言境界がその組に一つも無ければ、`wall` の既定境界が合成後に導出される (`derived`)。垂直の「既定は床」と対称の、水平の「既定は壁」— 未宣言の接触は「未定義」ではなく「壁」を意味する。既定の壁は扉を持たないため通れず、描画は素の宣言wallと同一。宣言がその組に一つでもあれば (edge限定含む) 導出しない。領域つきのexteriorとの接触にも導出される (接道長に算入される)。既定境界は正準JSONに出ない — 正準JSONは書かれた構成、意味は導出後のModelが持つ。

**開口の配置。** 比率 `at` は線分長に対する中心位置で、開口が線分に収まるようクランプされる。通り参照の明示位置はクランプされない — 中心±w/2 が線分から出ればエラー (許容範囲つき)、水平線分にY系・垂直線分にX系の参照もエラー。同じ線分上の開口は中心間距離 ≥ (w₁+w₂)/2 でなければエラー。

## 3. 垂直の導出と高さの不変量

**垂直隣接は宣言しない。** 連続するレベルの空間同士は、平面の重なりから垂直に隣接する。既定の解釈は「床がある」。例外だけを境界で宣言する: `stair` (通行可) / `shaft` (連続するが通行不可) / `void` (床の不在)。

**高さの不変量 (階高検査)。** 各空間について `天井高 (heff) + 上階のslab ≤ 階高 (次レベルzまで)` を検査し、超えれば食い込みエラー。`levels` がこの積み上がりをテキストの矩計として表示する。**void免除**: void境界で結ばれた下階空間は不変量を宣言的に免除される。被覆率 ≥99% (全面吹抜け) のときだけ階をまたぐ天井高を宣言できる — 部分吹抜けでは下階の天井高は階高内のまま。void空間の上側は `type:void` を想定 (違えば警告 — 実装とテストが正でありspecを合わせた。ADR-0013)。

## 4. 導出される性質

**半屋外 (isSemiOutdoor)。** 宣言ではなく導出: 外部 (`type:exterior`) に対して `open` または `air:1` の境界を持つ、領域つきの空間。バルコニー・テラス・屋外階段・庭がこれになる。面積表で別掲 (屋内床面積に算入しない)、採光で係数、平面で淡色/細線。

**庇下 (isCoveredAbove)。** 上に (どのレベルであれ) 空間が重なっているか。屋根の有無すら宣言でなく導出 — 採光の半屋外係数 (下記) が読む。

**通行可能性 (passable)。** wall は扉があるときだけ通行可。open・stair は常に通行可。shaft・void は通行不可。air:1 は遮蔽の話であって通行の話ではない (手すり壁は通れない)。

## 5. 検査 (check) の一覧

`check` の一次形式は構造化診断 (`checkDiagnostics` — ADR-0016): `code` (下表の台帳 = 実装の `DIAGNOSTIC_CODES`。テストが一致を機械検査する)、`severity` (コードの不変属性 — 重さを変えるときは新コードを切る)、`message` (日本語本文 — 位置接頭辞なし)、出所 (`line`/`file`)、対象パス (`path` — 境界は両パス)、関連位置 (`related` — 重複の既出側など)。`check` は互換の文字列形式 (`file:N行目: 本文`) を同件・同順で返す。エラーは構成が成立していないこと、警告は疑わしいことを言う。

## 6. 問い — 同じ記述の異なる読み方

**doors (避難・動線)。** 空間グラフ (§4の通行可能性で辺を張る) 上の最少扉数経路。`doorsBetween(from, to)` → 扉数と経由パス列、到達不能なら undefined。

**stats (面積)。** 屋内床面積 = 領域とレベルを持ち、void でも exterior でも半屋外でもない空間の壁芯面積の合計。レベル別小計・半屋外の別掲・ゾーン別 (パス接頭辞の合計 — 間取りに割っても住戸の言葉を保つ)・型別・use別 (zone→space継承後の実効use)。

**light (採光)。** 対象: `daylight:1` を書いた領域つき空間**だけ** — 採光の対象は宣言であり、型からは推定しない (既定は対象外。ADR-0020)。判定の分母をどの粒度に置くか (住戸まるごとか、割った室ごとか) は `daylight:1` を書く位置として書き手が決める。窓面積 = その空間の境界上の `h` を持つwindowの w×h の合計。係数: 窓の先の半屋外が**上に空間を持つ** (バルコニー下・庇下) なら0.7、上が開いていれば1.0。判定: 有効窓面積 ≥ 床面積/7 (補正係数なしの粗い判定)。

**site (敷地)。** 対象: `site:1` のゾーン。敷地面積 = polygonがあればシューレース、なければ敷地内空間+屋内投影の合併 — 宣言 (`area:` 測量値) と照合 (±0.05㎡)。不一致は `check` の警告にもなる (polygonがある場合 — CLI/API/MCPで同じ判定。ADR-0013)。接道 = 敷地ゾーン配下の空間と `road:幅員` を持つexteriorとの境界線分長の合計 (建物外壁が道路に面する分は数えない)。建築面積 = 屋内空間の水平投影の合併 (算入細則は粗い)。建蔽率・容積率はこれらの商。

**levels (矩計)。** レベルをz順に、階高 = 天井高 + slab + 余り の積み上がりとして表示する。

## 7. 描画 (plan) の規約

形は生成物 — 同じ構成から複数の形が出ることは欠陥ではない。svgPlanの規約: 空間は淡い面 (半屋外はさらに淡く)、壁は導出線分の黒帯 (t で太さ)、open境界は破線、air:1 は細実線、吹抜けは破線対角線 (下階には「上部吹抜け」の投影)、扉は吊元と1/4円の軌跡 (sliding/autoは戸袋側パネル)、窓は芯線、seg は色調変化、area は淡面+破線。通り芯と記号。最下階は配置図兼用で、敷地形状を一点二点鎖線の敷地境界線として描く (polygonを含めて紙面を確保)。
