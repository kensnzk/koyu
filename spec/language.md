# 言語リファレンス — .muro (author形式)

koyu v0.9.0 現在の記法の規範。意味論 (導出・検査・問い) は [semantics.md](semantics.md)、属性の契約は [vocabulary.md](vocabulary.md)。

## 1. 字句

**一行が一文。** 各行は `キーワード 位置引数... key:value...` の形をとる。トークンは空白区切り。`#` 以降は行末までコメント。値に空白や `#` を含めるときは `"..."` で囲む (引用符はトークンのどこに現れてもよく、閉じなければエラー)。字下げ (行頭の空白) された行は**直前の親行に従属する** — `boundary` の下の `door` / `window` / `seg`、`space` の下の `area`。空行は無視。

**属性 `key:value`。** キーは `:` の左、値は右 (値が空ならエラー)。値が数値の形 (`-?\d+(\.\d+)?`) なら数値として、それ以外は文字列として保持される。同一行内の同名キーの重複はエラー — 後勝ちの黙認はtypoとマージ事故を隠す (ADR-0013。アセット既定値のインスタンス上書き〈§6〉は二つの出所であって重複ではない)。解釈される属性 (★) は vocabulary.md の台帳が契約で、それ以外のk:vは自由に書けてそのまま運ばれる。

**単位と座標系。** 長さはmm。平面は X (東+)・Y (北+)、高さは z (上+)。線分上の比率位置は 0..1。面積の出力は㎡ (壁芯)。

## 2. 基盤の宣言 (base層が一度だけ持つ)

```
koyu 0.2                      # 版宣言 (base層でのみ・一度だけ)
name 街角の複合ビル             # 建物名 (残りの行全体、空白可)
unit mm                       # v0はmmのみ
grid X 0 6400 12800 19200     # X軸の通り芯座標 (昇順・2つ以上)。X1,X2,...が自動命名
grid Y 0 5600 7600 13200
level L1 0 h:3600 slab:600    # レベル: 名 z [h:天井高] [slab:床組み厚]
level L4..L10 11000 pitch:3000 h:2500 slab:450   # 範囲宣言 (等差)。pitch必須
```

`grid` は軸ごとに一度だけ (合成時はbase層で)。`name` も一度だけ (同文なら再宣言可)。`level` の範囲宣言 `L4..L10` は接頭辞+連番で、`z + pitch×k` に展開される。レベル名の重複はエラー。空間を持たないレベル (例: 屋上 `R`) を宣言すると最上階の高さ検査の上限になる。

**版の規範 (ADR-0017)。** このツールが対応する言語版は `0.1, 0.2`、宣言を省略した場合は最新版 `0.2` の意味論で読む (省略はツール版を跨いで意味安定ではない — 意味を固定したいファイルは版を書く)。版宣言はbase層 (entry) でのみ・一度だけ (合成順による黙った上書きを禁じる)。旧版 `0.1` は**意味保存の場合のみ**受理される — 既定境界 (§4) の導出が起きるファイルはエラーになり、境界を宣言するか `koyu 0.2` へ上げる。言語を変える変更は版を上げ、ADRに移行を書く。

### 通り参照とオフセット

座標の直書きは無い — 位置は常に通り芯の言葉で書く: `X2`、`X2+600`、`Y3-150`。範囲は `X1..X2+3200` のように両端を通り参照で書く。

## 3. space — 空間

```
space /L5/A/ldk ldk X1+3200..X2+3200 Y1..Y1+4000 + X2+3200..X3 Y1..Y1+2400 name:LDK floor:オーク
space /out/road-s exterior name:南側道路 road:12000
  area X1..X2 Y1-4600..Y1-2600 name:土間 floor:タイル      # 字下げ: 数えない分節
```

- **パスが同一性。** `/` 区切りの階層。パスの第一義は集計の階層で、先頭セグメントがレベル名ならそのレベルに属する。階を跨ぐくくり (メゾネット等) は `level:` 属性で明示する。
- **型は開かれた語彙** (第2位置引数、必須)。構造として解釈されるのは `exterior` (領域なし可・外部) と `void` (吹抜け — 床面積不算入・通行不可)。採光の対象は `unit` `room` `ldk` `bedroom` `living` (+ `hab:1/0` で増減)。
- **領域は矩形の合併。** `X?..X? Y?..Y?` を `+` で複数書ける (L字など)。領域を持たない空間 (exterior等) も可。同一空間内・空間同士の領域の重なりはエラー。
- **`area` (字下げ)** は室内の数えない分節: 領域+上書き属性のみ。面積・室数・グラフに影響しない (隔離則)。親の領域からのはみ出しは警告。
- **スパン展開**: パスの**先頭セグメント**が `L3..L10` の形なら、宣言済みレベルのz順の並びに展開される (各行のスパンは一つに揃える)。

## 4. boundary — 境界 (壁は関係であって物ではない)

```
boundary /L5/A/hall /L5/corridor t:180 spec:RC
  door D1 at:X4 name:玄関                    # 字下げ: 開口
  seg w:1800 at:X5 edge:S spec:受付ガラス      # 字下げ: 数えない分節
boundary /L1/hall /L2/void type:void          # 垂直の例外
```

- 二つの空間パスを結ぶ第一級の関係。壁芯線分は書かない — 両空間の割付から導出される (semantics.md §2)。接していない空間の境界はエラー。**同じ空間対への境界の重複 (edge限定まで同一) もエラー** — wall/openの食い違いを黙って通さない (ADR-0013)。edge限定の有無が混在する対は警告 (線分が重なる)。
- **接する空間の既定は壁 (ADR-0014)。** 同一レベルで平面が接する領域つき空間の組には、宣言が無ければ `wall` の既定境界が導出される — 垂直の「既定は床」と対称で、宣言は例外 (open・手すり) と属性・開口のためにある。領域を持たない空間 (exterior等) との境界は従来どおり宣言する (どの外部かの名指しが情報)。吹抜け (type:void) の縁も既定は壁 — 手すり (air:1) やopenは宣言する。既定境界は正準JSONには出ない。
- **type (kind) はトポロジーだけ**: 水平は `wall` (既定 — 物がある。扉がなければ通れない) / `open` (何もない — 常に通行可)。垂直は `stair` (通行可) / `shaft` (連続するが通行不可) / `void` (床の不在)。床は書かない — 垂直の隣接は平面の重なりから導出され、既定は床。壁境界を異なるレベル間に書くとエラー。
- **物の名は `spec` 語彙** (手すり・RC・LGS・カーテンウォール…)。ツールは解釈しない。
- **`air:1`** = 物はあるが外気・光を遮らない (手すり・柵・フェンス)。半屋外の導出・採光係数・細線描画に効く。
- **`t`** = 壁厚mm (芯振り分け。未指定の描画既定は100)。**`edge`** = 線分をa側 (先に書いた空間) の矩形から見た辺 N/E/S/W に限定する。
- **`stack 名 L1..L11 type:stair|shaft|void`** は垂直積層の一括宣言: 連続レベル対 `/Lk/名 | /Lk+1/名` に垂直境界を張る。

### 開口 (door / window)

- `door` は通行、`window` は採光 (通行しない)。**幅 `w` は必須** (アセット側でも可)。`h` は任意 (windowの採光計算は `h` を持つものだけ数える)。
- **アセット参照**: 先頭の非key:valueトークンはアセット名 (`door SD1 sill:800`)。アセットの属性が既定になり、インスタンスの属性が上書きする。kind不一致・未定義はエラー。
- **位置 `at`**: 比率 `0..1` (既定0.5 — 線分内に収まるようクランプ) または通り参照 `at:X2+450` (絶対位置 — クランプしない。はみ出し・軸違い〈水平線分はX系・垂直線分はY系〉はエラー)。同じ線分上の開口同士の重なりはエラー。
- **複数線分の辺選択 `edge`**、**開き勝手 `hinge`** (吊元: 水平線分はW/E、垂直線分はN/S。既定は始端側)・**`swing`** (開く側 a/b。既定はa=領域を持つ側)。`style` (hinged/sliding/auto) は平面の建具表現を変える。
- **`seg`** は境界上の数えない分節: 位置 (at/w/edge — 開口と同じ流儀) + 上書き属性。通行・接続に影響しない。

## 5. zone — 数える集約

```
zone /L3..L10/A name:Aタイプ use:exclusive
zone /site name:敷地 site:1 area:1097.80
```

幾何を持たず、パス接頭辞で配下の空間を束ねる。面積は配下の合計、`use` は配下に継承 (空間側の宣言が勝つ)。`site:1` は敷地の印で `site` の問いの対象になり、`area:` (測量値㎡) は導出面積と照合される。パスの重複はエラー、配下に空間が無ければ警告。

## 6. asset — 建具アセット

```
asset SD1 door w:800 h:2000 style:sliding name:片引き戸
```

参照される既定値の束 (RevitのFamily / USDのReference)。第4の要素ではない — 開口の属性の出所を一箇所にするだけ。名前の重複は (合成時も) エラー。

## 7. polygon — 敷地形状

```
polygon /site -2600,-7000 38000,-7000 38000,19600 2000,21000 -2600,15000
```

**この記法で唯一、格子に載らない自由頂点で「書かれる形」** (空間の領域もグリッド参照の矩形として書かれるが、任意の頂点列はpolygonだけ)。敷地の形は測量由来の所与であって設計の生成物ではないため、例外として認める。頂点は `x,y` のmm座標 (グリッドと同じ座標系) を3つ以上。site:1のゾーンパスに対応させる (対応が無ければ警告)。導出面積・建物のはみ出し検査・配置図の敷地境界線がここから出る (semantics.md §5)。隔離レイヤー (別ファイル+import) に置く運用を標準とする。重複はエラー。

## 8. import — 合成

```
import ./assets.muro
```

書かれたファイルからの相対パスでレイヤーを読み込み、**加算合成**する。base層 (entry) が基盤 (koyu/name/unit/grid/level) を一度だけ宣言し、各レイヤーは空間・境界・ゾーン・アセット・polygonを加える。規則:

- 同じレイヤーは一度だけ合成される (二重import・循環は冪等)。
- **衝突はビルドエラー**: 空間パス・ゾーンパス・アセット名・敷地形状の重複、grid/nameの再宣言。エラーは両者の出所 (`ファイル:行`) を言う。黙った上書きは無い (レイヤー強度は不採用)。
- 合成の入口は3つ: `parse` (単一ソース — importはエラー) / `parseFile` (fs — node) / `parseFiles` (仮想ファイル群 — ブラウザ)。checkのエラー・警告も出所レイヤーつきで返る。
- 正準JSONは合成後の単一モデルであり、importは残らない。

## 9. 既定値の一覧

| 項目 | 既定 |
|---|---|
| boundary type | `wall` |
| boundary t | なし (描画時のみ 100mm) |
| 接する空間の境界 | `wall` — 書かない。例外だけ宣言 (open / air:1 / 属性・開口つき — ADR-0014) |
| opening at | 0.5 (比率 — クランプあり) |
| opening hinge / swing | 線分の始端側 / a側 (領域を持つ方) |

| space h | レベルの h |
| 垂直の隣接 | 床 (slab) — 書かない。例外だけ宣言 (stair/shaft/void) |
| 面積算定 | 壁芯 |
