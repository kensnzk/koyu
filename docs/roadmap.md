## 残っている作業

### 1. 参照実装 `derive(model): Form`

**「参照実装は見た目を持たない」** ([spec/scope.md §6](../spec/scope.md))。いま形は消費者ごとに組み立てられている — `src/draw/plan.ts` は `segmentsFor` と `placeOpening` を呼び、ugatsu の `PlanView` と `buildScene` も同じ部品を別々に呼ぶ。**同じ部品から違う形が出る余地が構造的に残っている**ので、色も書体も注記文字列も持たない `Form` を一つの入口から返し、`src/draw/` と ugatsu はそれを描くだけにする。

これが立つまで、ugatsu 1.0 の凍結面「導出の一致」は検査しようがない。

### 2. 導出規則の明文化

共有辺と共線マージの条件、描かれた線の窓と残す側の決め方、床・天井・屋根の輪郭と z 範囲と厚み、段割りの式、壁厚の既定と `air:1` の扱い — これらはいま実装の定数にしかない。**規則が消費者ごとに違えば、同じ原本から違う建物が出る。それは原本ではない。**

### 3. 機械形式の版と決定性

正準JSONに形式そのものの版を与える (`koyu` フィールドは言語版であって形式版ではない)。キーの照合順と Unicode 正規化を規範として書き下す — バイトが変わるので 1.0 の前にしか決められない。property test の母集団を全構文へ広げ、単射性 (違う構成なら違うバイト) を足す。

### 4. 公開面の掃除

`src/index.ts` の `export *` を明示 export に置き換える。利用者ゼロの export を落とす。CLI の全サブコマンドに契約テスト (終了コード・一行目の形・誤った呼び方) を立てる。`files` に `spec/` を同梱する。

### 5. 同一性の生成規則

uid を機械が付与するときに、何から作り、どこまで衝突しないことを保証するか。**1.0 では opt-in のまま**にする判断もありうる — その場合はそう明記する。

## 1.0 の後 — 伸ばす領域

**core はもう動かない。**伸ばすのは検証と表現である ([spec/scope.md §1](../spec/scope.md))。

- **検証** — 区画・避難距離・排煙・用途別の面積率。管轄が二つ目を持ったら章を割る。[spec/validation.md](../spec/validation.md) に足すだけで、言語の版は動かない
- **表現 (ugatsu)** — 寸法線・通り芯記号・建具の作図表現・縮尺・勾配屋根。**図面の精度は凍結の対象ではない**
- **外部との接続** — RDF/BOT 出力、測地、IFC からの一方向の取り込み。**コアの外に置く**

## 扱わないこと

原本における幾何 (例外は所与 — 敷地形状)。配置の仕組み (内包は座を与えない)。建築的な判定を原本の契約に含めること。実務解像度の追求 — **カバー率は価値ではない**。往復互換。曲面と自由形状。オーサリングツール。
