# koyu 1.0.0 への行程

方針は [policy.md](policy.md) が、範囲の規範は [spec/scope.md](../spec/scope.md) が持つ。この頁は**残りの作業だけ**を持つ。

**1.0.0 は機能の完成ではない。壊さないと約束する面の確定である。**したがって行程は「何を作るか」ではなく「何を凍らせられる状態にするか」で切ってある。

現在は **koyu 1.0.0-rc.1 / muro 1.0** である。**rc は「凍らせる用意ができた面を先に固定し、残りを名指しで残す」ための版である** ([ADR-0038](decisions/0038-version-1-0-rc.md))。

探求の経緯 (M0〜M1.6 の各段で何を確かめ、何を見送ったか) は [log/](log/) と [decisions/](decisions/) にある。行程表としては畳んだ — 済んだ道のりを行程表に置いておくと、残りが見えなくなる。

## 残っている作業 — 描かれた線が絡む四つの不整合

**規則を書き下したことが、規則の破れを見せた。**[spec/scope.md §6](../spec/scope.md) は「この記述からは、一意な形が作れなければならない」と約束しているが、`spec/derivation.md` を書く過程で、**同じ原本から二つの形が出る経路が四つ**見つかった。どれも `line` (描かれた線 — [ADR-0022](decisions/0022-lines.md)) が絡む。すべて実測してある。

| # | 経路 | 実測 |
|---|---|---|
| 1 | 外皮を切る線で、`boundary` の a 側に領域を持たない空間を書くと**残す側が反転する** | 34㎡ ↔ 26㎡。`check` は緑 |
| 2 | 線の端点の**書き順**が開口の `at:` の起点を決めるのに、正準JSONは書き順を正規化する | **正準JSONがバイト同一 (sha256 一致) のまま扉が別の位置に出る** — (2400,1200) ↔ (3600,4800) |
| 3 | `line` を持つ境界の**宣言順**で導出面積が変わる | 67.5㎡ ↔ 72.0㎡ |
| 4 | `drawnCut` を呼ぶ時点で母集団が違うため、18㎡を実際に落とした線に LIN03「何も切っていない」が誤報される | — |

**2 が最も重い。**正準形の存在理由は「同じ構成なら常に同じバイト列、違う構成なら必ず違うバイト列」であり ([canonical-json.md](../spec/canonical-json.md))、2 はその後半を破っている。

**この四つを一つの ADR で扱う** ([ADR-0040](decisions/0040-derive-reference.md) 代償4)。どれも「どちらを正とするか」の判断が要り、正準JSONの照合順と診断の母集団まで届くので、個別に直すと互いに矛盾する。`derive()` は現在の振る舞いを忠実に写しており、ゴールデンがそれを固定しているので、**直した瞬間にゴールデンが落ちて気づける。**

## 1.0 の後 — 伸ばす領域

**core はもう動かない。**伸ばすのは検証と表現である ([spec/scope.md §1](../spec/scope.md))。

- **検証** — 区画・避難距離・排煙・用途別の面積率。管轄が二つ目を持ったら章を割る。[spec/validation.md](../spec/validation.md) に足すだけで、言語の版は動かない
- **表現 (ugatsu)** — 寸法線・通り芯記号・建具の作図表現・縮尺・勾配屋根。**図面の精度は凍結の対象ではない**
- **外部との接続** — RDF/BOT 出力、測地、IFC からの一方向の取り込み。**コアの外に置く**

## 扱わないこと

原本における幾何 (例外は所与 — 敷地形状)。配置の仕組み (内包は座を与えない)。建築的な判定を原本の契約に含めること。実務解像度の追求 — **カバー率は価値ではない**。往復互換。曲面と自由形状。オーサリングツール。
