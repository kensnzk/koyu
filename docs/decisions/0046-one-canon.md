# ADR-0046: 正典を一つにする — 統治の反転を記録し、`spec/` と `guide/` を畳む

日付: 2026-07-30 / 状態: 採用 (v0.16.0) / 起点: [docs/reviews/2026-07-28-docs-ia-rebuild.md](../reviews/2026-07-28-docs-ia-rebuild.md) §7.1・§10.1 (「持ち方は別途検討」) / 関連: [ADR-0037](0037-public-api-surface.md) (公開面 — `./spec/*` の決定を覆す)・[ADR-0016](0016-diagnostic-contract.md)・[ADR-0028](0028-diagnostics-per-declaration.md)・[ADR-0033](0033-attribute-tiers.md)

## 文脈

**この ADR は二つのことを記録する。**一つは既に起きた決定の事後記録で、もう一つは保留されていた決定の解消である。

### 一. 統治の反転には ADR が無かった

2026-07-28 のコミット `d4ddd67` が情報設計をやり直し、**公開ドキュメントを正典にした。**「ADR と `spec/` は公開しない」「公開文書は自己完結する」を決め、権限委譲の文 約160 を書き切り、`gate:docs` で機械化した。

**これは統治規則の反転である。**以前は「規範は `spec/` が所有し、食い違ったら `spec/` が正しい」だった。[AGENTS.md](../../AGENTS.md) 自身が「覆すときは新しい ADR を書く」と定めているのに、**この反転には ADR が無かった。**理由・棄却案・受容したリスクは 43KB の設計レビューとコミット本文に残っているが、決定の台帳には無い。

擁護できる点もある。覆された旧統治 (guide/spec 二書体制) 自体も ADR を持たずに成立しており、非対称な手抜きではない。だが規律は規律である。**この節がその欠落を埋める。**

### 二. `spec/` の去就は「未決」と記録されていた

設計レビュー §10.1 は二案を名指しして保留した — 「残して内部台帳とするか、公開ドキュメントに吸収して消すか」。そして帰結をこう書いた。

> **二重の正が一時的に存在する。**同期の仕組みは無い。これは既知の負債であり、`spec/` の持ち方が決まるまでの過渡状態である

**負債は利息を払っていた。**実測で三つ。

1. **`spec/` が実装の逆を教えていた。**`spec/tools.md` は「段数と踏面は `check` の RUN06 が検査する」と書き続けていたが、RUN06 は退役して `stair.proportion` (validate) へ移っている。`spec/derivation.md` も RUN06/RUN07 を現役として参照していた。`d4ddd67` 自身が「`spec/` が後の ADR に追随せず古い事実を現在形で主張している箇所が 7 件あった」と数え、それらを新しい `docs/` 側で直して `spec/` は放置した。
2. **機械が縛っていたのは正典ではない側だった。**テスト 6 箇所が `spec/` をファイルとして台帳に読んでいた。最悪の位置は `test/public-api.test.ts` で、**凍る八面の八番目「公開 API と CLI」の台帳が `spec/tools.md`** だった。結果として、正でない側だけが正確に保たれ、正である側が無防備に古びる構えになっていた。
3. **`spec/` は npm パッケージに入っていた。**`files` と `exports["./spec/*"]` の両方にあり、`npm pack` に 22 ファイル (日英11ずつ) が同梱されていた。**`docs/` は 0 ファイルである。**つまり「`spec/` は公開されない」はサイトについてのみ真で、**パッケージ利用者が受け取るのは古びた自称規範の側だった。**しかも `docs/reference/api/index.md` が記録するモジュール入口は 4 つ、実際の宣言は 8 つで、`./spec/*` `./examples/*` `./syntax` `./package.json` は台帳の外にあった。

そして地図が矛盾していた。[AGENTS.md](../../AGENTS.md) は `spec/` `guide/` を「旧レイアウトの残骸。**参照しない**」と宣言しながら、**自分自身が 14 箇所そこへ誘導していた** (`docs/reference/` への参照は 4 箇所)。誘導先での呼び方は「契約は `spec/tools.md`」「規範の台帳は `spec/semantics.md`」「診断の全65コードは `guide/diagnostics.md`」であり、記法を知らない読者は `guide/start.md` へ送られた。**全エージェントが無条件に読む唯一の地図が、読むなと書いた木を指していた。**これは読者の不注意では避けられない。

## 決定

**正典は一つ、`docs/` である。`spec/` と `guide/` を畳んで消す** (レビュー §10.1 の二案目)。

**1. 地図を先に直す。**`AGENTS.md` の 14 リンクを `docs/` の対応頁へ向けた (18リンク、実在を検査済み)。併せて事実を三つ改めた — 「持ち方は未決」→ 畳むと決定、「`spec/` は公開されない」→ サイトには出ないが npm には入っている (畳むときに外す)、頁数 165 → 167 (`gate:docs` が数える実数)。

**2. 機械の縛りを正典へ移す。**移したのは 6 件 — 導出定数17個と公差7個の表、診断65コードの code→severity、判定15規則の表、規則ごとの節と level、公開面の名の集合 (実行時59・型77)、言語版の台帳。いずれも日英とも縛る。`docs/reference/api/index.md` には**面の全部を一枚で持つ表**を新設した (14行、モジュール構成から機械的に起こしたので恣意的な割り振りは無い)。`docs/reference/form/constants.md` は「この頁の表と実装の一致はテストが縛る」と書いていながら縛られていなかったので、マーカーを足して**その主張を真にした**。

**3. 語彙の縛りは実装へ移す。**文法の色分けは文書の表ではなく `ATTR_LEDGER` そのものと突き合わせる。掟7 が「実装の唯一の出所は `ATTR_LEDGER`」と定めており、表では層 (structure / interpreted / carry) を表せないため、旧版は表が落とす 5 キーを手で補っていた。

**4. 文書の門番を正典へ向ける。**`guide/**` を走査していた非乖離の門番 (```muro が実際に通り、```muro-bad が実際に落ちる) を `docs/` の公開頁へ向けた。ja/en の対応検査も `spec`/`guide` の二本から `docs` へ移した。**どちらも移さなければ、削除と同時に検査が黙って空振りになる。**

**5. パッケージから外す。**`files` から `spec` を、`exports` から `./spec/*` を落とした。これは [ADR-0037](0037-public-api-surface.md) の「契約はパッケージの中にある」という決定の該当部分を覆す — 契約は `docs/` にあり、`docs/` は同梱しない。代わりに**宣言したサブパスがすべて API リファレンスに載っていることを機械が縛る**ようにし、その過程で台帳の外にいた `./examples/*` と `./syntax` を文書化した。

**6. `spec/` と `guide/` を削除する。**サイトの publisher は既に `docs/` だけを出していた (`docs/reference` の存在が切替の合図で、旧レイアウトの枝は死んでいた) ので、死んだ枝と旧ルートも落とした。README (日英) を `docs/` へ向け直した。

## 帰結

**正典が古びたときに落ちるものが増えた。**移送の過程で正典自身の誤りが 7 件出た。うち 5 件は移送しなければ見つからなかった。

- `json/index.md` が柱の通り名を「内容の正準順」に数えていた (実際は通りの並び順で、同じ `docs` の `schema.md` が正しく書いていた — **docs 内部の食い違い**)
- `form/plan.md` が敷地境界線を「一点鎖線」と書いていた (実装は二点鎖線。通り芯が一点鎖線なので、線種で見分ける作図慣習どおり)
- `form/plan.md` の「可視区間が 900mm を下回れば矢印は出ない」が境界で誤っていた (実装は厳密な超過なので、ちょうど 900mm でも出ない)
- `validate/` の判定例 34 ブロック (日英) が ```muro-bad / ```muro-warn を名乗っていた。**判定は core の診断ではない** — 正しい印は ```muro-fail / ```muro-caution である。付け替えたことで、34 例が実際に正しい判定を出すことを門番が確かめるようになった
- 公開頁に**印の無い裸のフェンス**が 28 箇所あった (印の欠落は検証が抜ける最も起きやすい形である)
- `json/schema.md` の JSON 断片 16 ブロックが ```json を名乗っていた (全文書として読めないので ```json-part を切った)
- `why/open-vocabulary.md` が英語版にだけ `koyu light` の出力ブロックを持っていた (日本語版に足した。貼った出力は実行して得たものである)

**移送で分かった構えの事実も三つ。**`SYN01` は個別のコードではないので節を持たない (頁自身がそう書いている) — 台帳の集合一致から明示的に除外した。診断は**宣言ごとに一件**なので (ADR-0028)、1.0 の語を三つ使う例は VER04 を三件出す — 門番の「ちょうど一件」を「自分のコードだけ」に改めた。ja/en の逐語一致は正典では成り立たない — 正典は例の表示名も図のラベルも訳すので、比べるのは構造 (ブロック数・並び・印・行数) にした。**そのぶん「貼った出力が実物か」は日英比較では答えられない。**この隙間はテストのコメントに明記した。

**残っている負債。**`spec/` の 5 頁が版を名乗ることを縛っていた検査は消えた — `docs/` は方針として本文に版を積まないので、移す先が無い。ADR 18 本・59 箇所が `spec/` へ相対リンクしており、それらは死んだ。ADR は後から直さないので、これは**記録が指す先が消えた**という事実として残る。
