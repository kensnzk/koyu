# ADR-0051: 構成の事実は型の位置から出る

- 状態: 採用
- 日付: 2026-08-02

## 文脈

`space` の第2位置引数 (型) は開かれた語彙である。そこに `exterior` と `void` — 外部であること、床が無いこと — が書かれ、構造として解釈されていた。

ADR-0033 決定4 はこの二語に**編集距離1の見張り**を置いた。`exteriorr` と一字余分に打った瞬間にその空間は外部でなくなり、実測で延床が 16.20㎡ から 32.40㎡ へ倍増しながら `check` は緑で通ったからである。

同じ ADR-0033 の「代替案」は、今回採る案を既に検討していた。

> 「**構造二語を属性へ移す (`exterior:1` / `void:1`) 案は筋が良い** — `daylight` で同じ判断を既に下している (ADR-0020)。だが examples 全15棟と guide の全 muro ブロックの書き換えを伴い、得るものは「編集距離1の守り」と変わらない。**1.0 の後、実例が要求したときに再訪する。**」

却下の理由は原理ではなく移行コストであり、その先送りの綴りは方針 §17 が明文で禁じている形だった。

> 「**「実例が要求したら採否を決める」という留保つきの決定を書かない。留保は、そのまま拡張の入口になる。**」

再訪の時が来たのは実例が要求したからではない。**留保が最初から無効だったからである。**

三つの事実が、見張りが設計でないことを示している。

1. **広げられない。**編集距離2まで拒めば `void` に対して `road` と `wood` が入る。どちらも人が正当に書く語である。守れる範囲がヒューリスティックの都合で決まっているとき、それは規則ではない。
2. **テストが無い。**`grep -rn "exteriorr\|guardStructuralType" test/ conformance/` は空だった。掟3 (ADR + テスト + 公開文書の三点セット) を、型の位置を守る唯一の仕掛けだけが満たしていなかった。
3. **公開文書が嘘を言っていた。**`docs/reference/diagnostics/syn.md:126` は日英とも「型の綴りで判定が消えることは無い」と書き、しかもそれを**開いた位置の正当化として**差し出していた。実測すると `corridorr` の一字で `access.backofhouse` が消え、`shafr` は逆に偽の `access.unreachable` を生んだ。

そして方針 §11-5 は、この欠陥を名指しで 1.0 のブロッカーに挙げていた。

> 「書いたものが黙って消える経路、宣言していない側が黙って落ちる経路、**種別の綴り違いが黙って通る経路**——この種の経路が残っている限り、1.0 は切れない」

## 決定

**1. `outside` と `void` を台帳の鍵にする。**どちらも `space` の解釈層、値域は `0` / `1`。

```muro
space /out name:南側道路 road:6000 outside:1
space /L2/hole X1..X2 Y1..Y2 name:吹抜け void:1
```

層を「構造」ではなく「解釈」にしたのは、台帳における `structure` が「parse が typed field へ持ち上げるので check の時点では attrs に残らない」を意味するからである。この二つは attrs に残る。実装上 `tier` が効くのは `diagnose.ts` の一箇所 (運搬層は値を見ない) だけなので、値域の検査はどちらでも掛かる。**嘘を書かない方を採った** — `ceiling: one(0,1)` と同じ構えである。

**2. 型の位置は core から完全に切り離す。**`isOutside(s)` / `isVoid(s)` を `model.ts` に置き、core と描画の型読み十数箇所をすべてそこへ通す。`test/vocabulary.test.ts` が `src/core/` と `src/draw/` に「型を文字列リテラルと比べる行」が一つも無いことを機械で守る。**これが今回の受入条件である** — 「今たまたま真」を「破れない」に変える一行だからである。

**3. `guardStructuralType` と `nearBy1` を削除する。**守る語が型の位置から出たので、見張りごと消えた。綴りを守るのは台帳になった — `outsid:1` は ATT03、`void:2` は ATT02 である。**新しい診断コードはゼロ**であり、既存の二つを再利用しただけである。

**4. 型の位置を任意にする。**必須である理由が無くなったからである。何も読まない位置を必須にしておくと、書き手は無意味な語を選ばされる。書かなければ正準形に `type` の鍵は現れない — **既定を捏造しない** (why/silence.md)。`Space.type` と `FormSpace.type` は `string | undefined` になった。

**5. `FormSpace` に `outside` / `void` の導出値を足す。**描画が型を読んでいたのを、導出された事実を読むように変える。消費側 (ugatsu・product) も同じものを読める。

**6. 正準 JSON の形式版を `koyu-canonical/1.1` に上げる。**常に在った鍵が任意になったので、読み手にとっては契約の変更である。既存の文書のバイトは変わらない (型を書いた空間は今までどおり `type` を出す) ので minor。**言語の版 (`muro 1.0`) は動かさない** — stability.md §意味保存 は導出物 (正準 JSON・グラフ・集計・SVG) の不変性を指し、これは綴りの契約であって導出物の意味ではない。パッケージは 0.16.0 → 0.17.0。

**7. `ATTR_LEDGER` と `isOutside` / `isVoid` / `RUN_KEYS` を公開する。**台帳を公開面から出していなかった間、消費側のアプリは「この鍵はこの要素に書けるか」を答えるために台帳を手で写すしかなかった。構造を台帳へ移した以上、その台帳が読めなければ意味がない。

**8. 検証 (`src/validate/`) の型読みは直さない。**`access.ts` は `shaft` `stair` `corridor` `backyard` と `use:` の三値を読み続ける。scope.md が core (凍る・きれいでなければならない) と validate (凍らない・汚くてよい) を分けている以上、これは領域の分離の帰結であって不整合ではない。**ただし文書が読んでいないふりをするのをやめた** — `validate/access.md` に「`void:1` は台帳が綴りを守るが `shaft` は自由語なので `shaftt` で黙って掛からなくなる」と書いた。

## 代替案

**型の位置を閉じた列挙にする (`interior` / `exterior` / `void` + 逃げ道)。**IFC の `PredefinedType` + `USERDEFINED` がこの形であり、同じドメインでの成熟した答えではある。採らなかったのは、scope.md が凍結面として「名前空間つき台帳」を「見ていないことと見て問題がないことを区別できる**唯一の形**」と名指しているからである。属性へ移すことは新しい設計ではなく、**既にある設計を適用すること**で済む — 新しい機構ゼロ、新しい診断コードゼロ、新しい文書ページゼロ。

**型の位置に名前空間を要求する (`acme.厨房`)。**CSS の `--` や HTML の `data-` と同じ構え。だが `厨房` と書きたい設計者に `local.厨房` を強いることになり、開かれた語彙という主張の実質を失う。core が読む語が二つしか無いのに、その二つを守るために語彙全体を閉じるのは釣り合わない。

**見張りを編集距離2に広げる。**`road` と `wood` が `void` の距離2に入るので採れない。ADR-0033 が既に同じ理由で却下している。

**何もせず、文書だけ直す。**`syn.md` の偽の文を消せば矛盾は消える。だが穴は残り、方針 §11-5 が名指したブロッカーも残る。そして「見張りにテストが無い」という掟3 違反も残る。

## 帰結と代償

**得たもの。**「型の語彙は開いている」が例外なしに言えるようになった。判定の入口は全て宣言の側にあり (`outside` `void` `daylight` `road` `site` `use`)、そのどれもが台帳に載っていて綴りを守られる。ADR-0020 が `daylight` について下した判断が、残り二語にも及んだ。

**実測で確かめたこと。**同梱9例の `stats` の出力が移行の前後で**バイト一致**する (型の列が `(untyped)` になる行を除いて)。121 宣言を書き換えて延べ面積が 1 ㎡ も動いていない。`Form` も、新しい二つの真偽値と落ちたラベルを除いて 3,194,588 バイトが一致する。

**代償1: 正準 JSON の形式版が動いた。**79 のファイルが `koyu-canonical/1.0` を埋め込んでいたので、conformance の期待値ごと書き換えた。形式版が**バイトの中に在る**以上、minor の追加でも全ての正準バイト期待値が動く。これは形式版の設計の代償であって今回のものではないが、次に minor を上げるときも同じだけ動く。

**代償2: 型を書かない空間の集計に見出しが要る。**`stats` は `(untyped)` にまとめる。MCP が `use` の欠損に `"(unspecified)"` を書く前例に倣った。**その語はその空間の型ではない** — 集計の見出しである。

**代償3: 型と `name:` の重複が露わになった。**同梱例で型と `name:` は 97% (456/469) 共起し、`name` から型はほぼ関数である (284 のうち食い違う 7 例は全て同義語衝突、つまりバグ)。`shop` と型付けられた「クリニック」と「フィットネス」のように、型が `name:` の保つ区別を消している行もある。**この頁ではその問いに答えない** — 1,042 行に書かれ図面に刷られているものを同じ変更で消すのは乱暴だからである。だが「なぜ二つあるのか」は、この変更の後に初めて綺麗に問える。

**残しておく事実。**ADR-0020 の 40 行目は `LEGACY_DAYLIT` が `src/check.ts` に在ると書いている。その後ファイルが割れ、現在地は `src/core/diagnose.ts` である。**ADR は追記専用なので 0020 は編集しない** — ここに記録する。
