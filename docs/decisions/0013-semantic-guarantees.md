# ADR-0013: 意味の保証 — 正準JSONの無損失化・境界の同一性・書き込みの門番

日付: 2026-07-25 / 状態: 採用 (v0.9) / 起点: 外部レビュー ([docs/reviews/2026-07-25-dsl-review.md](../reviews/2026-07-25-dsl-review.md)、検証と方向性は [同評価計画](../reviews/2026-07-25-evaluation-and-direction-plan.md))

## 文脈

外部レビューが、koyuの約束と実装の間の欠陥を11件指摘し、全件を最小ケースで検証した。重いものは三つ: (1) 正準JSONが境界のa/b向きを捨てるため、`swing`の開く側が違う二つのモデルが**バイト同一のJSONになる** (「diffとレイヤー合成の土台」の約束の裏切り)。(2) 同じ空間対へ`wall`と`type:open`を同時に宣言してもcheckが緑で、通行グラフはopen側で0枚通行になる。(3) MCPの`write_layer`が書いてから検査するため、parse不能な内容が原本を壊し、以後の全ツールが死ぬ。加えて、凹敷地のはみ出し検査が四隅だけ、敷地面積の照合が仕様にあって実装に無い、属性の後勝ちがtypoを隠す、`koyu 0.1`の版が検証されない、npm/lockfile/CITATION/READMEの版と数値が乖離 — いずれも「機能を増やす前に、意味を固める」べき欠陥である。

## 決定

**1. 正準JSONは無損失かつ宣言順に依らない。** 境界に `a` キー (書かれた向き — `edge`/`swing`はこの側から読む) を保存する。宣言順に意味の無い配列 (openings・segs・areas・領域合併・同一betweenの境界) は内容の正準順に並べる — 同じ構成を別の行順で書いても同じバイト列が出る。「書かれた表記を保存する」原則は向きにも適用する: a/bの向きは表記であり、正準形は語り直さない (向きの絶対参照化 `swing-into:/パス` は将来の言語版の論点として保留)。segの明示位置 (`at:X5`) は仕様どおり通り参照のまま保存する (実装が数値へ落としていたのを修正)。

**2. 境界の同一性は (無順序の空間対, edge限定) で定義し、重複はエラー。** wall/openの食い違いはこの検査が捕まえる。edge限定の有無が混在する対は線分が重なるため警告。「同じ関係を二度書けない」はパス・アセット・polygonの重複エラーと同じ規律の適用である。

**3. 検査の穴を塞ぐ。** 敷地のはみ出しは四隅の内包に加えて多角形頂点の入り込みと辺の内部交差を見る (凹敷地で正しい)。敷地形状の自己交差・重複頂点はエラー。宣言面積と導出面積の照合 (±0.05㎡ — 仕様には既にあった) をcheckの警告として実装し、CLI/API/MCPで同じ判定にする (`site`は`areaMatch`を返す)。同一行内の属性キー重複はエラー (アセット既定値のインスタンス上書きは二つの出所であり対象外)。対応しない言語版 (`koyu 0.1`以外) はエラー — 言語を変える変更は版を上げる。

**4. MCPの門番は書き込みの前に立つ。** `write_layer`は差し替え内容で仮想合成 (`parseFileWith` — overlay付きのfs合成) し、parse不能なら原本に触れない。checkのエラーは返すが書き込みは行う — 複数レイヤーにまたがる編集の途中状態を禁じると往復が成立しない (門番は往復の中にある)。書き込みは同一ディレクトリのtmp+renameでatomic。ディレクトリ境界は文字列prefixでなく相対パスで検査し (兄弟prefix `dir-esc/` への脱出を塞ぐ)、symlinkはrealpathで検査する。

**5. 合成の参加記録をModelが持つ。** `model.layers` (合成順) — grid/levelしか持たないレイヤーも記録され、MCPの`layers`が要素の出所からの再構成で取りこぼす欠陥を塞ぐ。

**6. リリース情報は同期し、テストが守る。** package / lockfile / CITATION.cff / spec各文書 / MCP serverInfo の版一致を `test/release.test.ts` が検査する。READMEの数値 (実装行数・ファイル数・行数) を実測に合わせ、部材の形と空間の領域の区別 — 原本に書かれるのは空間の領域と境界の関係、生成されるのは部材の形 — を主要文書の文言に通す。

## 代替案

**a/bを保存せず方向属性を絶対参照へ正規化する** (`swing-into:/L5/A/hall`) は正しい終着だが、author形式の変更 (言語版の引き上げ) を要し、exterior境界のedge意味論の再定義も絡む — `a`キー1つの追加で無損失は達成できるため、正規化は将来の版に譲る。**checkエラーでも書き込みを拒否する**案は、複数レイヤーにまたがる編集の途中状態を不可能にしてエージェントの往復をデッドロックさせる。**重複境界を後勝ちマージする**案はレイヤー強度 (不採用 — ADR-0010) の再導入に等しい。**属性後勝ちの維持** (旧spec) は仕様化されていた挙動だが、typo・マージ事故を隠す価値が無い — 仕様ごと改める。

## 帰結と代償

正準JSONは「意味が同じならバイト同一、バイトが同じなら意味も同一」に一歩近づき、diff・ハッシュ・外部射影の土台の約束が実体を持つ。矛盾した境界はビルドで止まり、エージェントの書き込みは原本を壊せない。代償: 正準JSONのスキーマが変わる (`a`キー追加・配列の並び) ため、旧JSONとのバイト比較は成立しない — 正準JSONを保存している利用者は再生成が要る。同一行の属性重複と重複境界がエラーになるのは非互換だが、既存の全サンプル・全テストは影響を受けなかった (重複は事故のみが書く形)。数十行の検査追加であり、依存ゼロと実装の小ささは保たれる。次はレビューの示す順序どおり、診断契約 (code/severity/range) と境界の既定 (接する空間の自動wall) をADRで決める。
