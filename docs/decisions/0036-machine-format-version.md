# ADR-0036: 機械形式の版と決定性 — 形式が自分を名乗り、バイトの並びを規範が決める

日付: 2026-07-27 / 状態: 採用 (v0.16.0、言語版 muro 1.0) / 起点: [方針の総覧](../policy.md) §10・§11-6

## 文脈

1.0.0 が凍らせる八つの面の一つが機械形式で、方針はその約束を「**版フィールドを持つ。同じ入力からは同じバイト列が出る**」と書いている。実測すると、v0.15 の正準JSONはそのどちらも満たしていなかった。

**第一に、形式が自分の版を名乗っていない。**文書の先頭にあるのは `"koyu": "0.5"` で、これは**言語版**である。形式の綴りは言語と独立に動いてきた — 境界の向き (`a` キー) の追加 ([ADR-0013](0013-semantic-guarantees.md)) は言語を一語も変えずに正準JSONのバイトを変えている。名乗っていない以上、消費者は自分が読んでいる綴りが何なのかを文書から知れない。

**第二に、その `koyu` の値が、著者の書いていない版でありうる。**版宣言を省いた原本は「そのツールの最新版」として読まれ ([ADR-0017](0017-language-versioning.md))、その値が刻まれる。ツールの既定が動いた日に、**同じ入力から違うバイトが出る**。決定性は形式の約束なのに、ツールの既定に預けられていた。

**第三に、バイト決定性の要が規範として書かれていない。**キーの照合順と Unicode 正規化 — この二つが定まらなければ「同じ入力から同じバイト」は言葉にすぎない。実装は JavaScript の既定に乗っていた。実測すると、二つとも実害がある。

| 実測したこと | 起きていたこと |
|---|---|
| `[𠮟, 﨑].sort()` — JSの既定は UTF-16 コード単位順 | 𠮟 (U+20B9F) が先に来る。UTF-8 のバイト順では `EF A8 91` (﨑) が `F0 A0 AE 9F` (𠮟) より前なので、**文書が自分自身のバイトの昇順に並んでいない**。どちらも日本語の実在の字である (𠮟る・宮﨑) |
| `が` (U+304C) と `か`+`゙` (U+304B U+3099) | 正規化していないので別の文字列である。名前に書けば同じ建物が **535バイトと538バイトの別の文書**になり、パスに書けば**見分けのつかない二つの空間**が同じ文書に並ぶ (パス重複のエラーも出ない) |

**バイトが変わる決定なので、1.0 の前にしか下せない。**

そして**単射性がほぼ未検査だった。**正準性の property test が見ていたのは「並べ替えても同じ」だけで、母集団は空間・境界・開口・ゾーンの四つ。柱も描かれた線も area も seg もアセットも polygon も帯もレベル範囲もメゾネットも、一つも生成されていなかった。**「違う構成なら違うバイト」— この形式の存在理由の半分 — を縛るテストは無かった。**すべてを捨てて `{}` を返す実装が、あの property を緑にできる。

## 決定

**1. 文書は自分の綴りの版を最初に名乗る。**`"format": "koyu-canonical/1.0"` を最上位の第一キーに置く。数えるのは**綴りだけ**である — minorはキーが増えたとき (増えたキーを持たない文書のバイトは変わらない)、majorは既存のキーの名前・並び・照合順・正規化・数の綴りが変わったとき (既存の文書のバイトが変わる)。値に名を含めるのは、`"koyu": "0.5"` と並んだときに**どちらが何の版かが一行で伝わる**ようにするためである。

**2. `koyu` は書かれた版宣言の素通しであり、書かれていなければ出ない。**省略規則 (値の無いキーは出力しない) を版にも適用しただけである。著者が書いていない版を名乗らせないためであり、**ツールの既定が動いてもバイトが動かないようにするため**である。意味を固定したい原本は `koyu 0.5` と書く — その助言は language.md に既にある。

**3. 照合順は符号位置の昇順であり、これは出力される UTF-8 バイトの昇順に等しい。**実装は `compareCanonical` (`src/core/model.ts`) で、JavaScript の `<` と既定の `sort` は使わない。**同時に「何が並ぶのか」も書き下した** — 規則1は「すべてのオブジェクトキーはソートされる」と書いていたが、実測すると最上位は `unit` の後に `grid` が来る。**記録の形のキーはスキーマの固定順、原本に由来するキー (レベル名・パス・アセット名・属性キー) が照合順**である。文書が実装と食い違っていたので、文書を直した。

**4. 文字は NFC である。**原本は読み込みのときに正規化され、**同一性 (パス・uid・名) もそこで決まる**。`が` を「か + 濁点」と綴った空間は、合成済みの `が` と綴った空間と同じ空間であり、両方書けばパスの重複エラーになる。**NFKC は採らない** — `㎡` を `m2` に、`①` を `1` に書き換えてしまい、それは「書かれた表記を保存する」(規則3) に反する。

**5. property test の母集団を全構文へ広げ、単射性の property を足す。**生成器は柱・描かれた線・area・seg・アセット・polygon・帯・レベル範囲・メゾネット・地下・名前空間つき属性を毎回書き、`COVERAGE` の14項目が正準JSONに現れることと、生成した模型が `check` のエラー0件であることを縛る。単射性は**意味のある一箇所の変更**26種で縛る — 適用できたら必ずバイトが変わり、一度も適用できなかった変更があればテストが落ちる (縛っているつもりで何も縛っていない状態を作らないため)。

## 代替案

**形式版を持たず言語版に相乗りする** (scope.md §9 が元々そう書いていた) 案は、綴りが言語と独立に動くという事実に反する。`a` キーの追加が反例であり、逆に言語版が上がっても綴りが変わらないことはある。

**`format` の値を裸の数 (`"1.0"`) にする**案は、`"koyu": "0.5"` と並んだときに読者がどちらの版か判じられない。**版が二つ並ぶ文書で、名の無い数は読めない。**

**版宣言を必須にする** (省略をエラーにする) 案は決定性を回復するが、言語の破壊的変更である。省略の意味は language.md が既に定義しているので、**形式の側が刻まないだけで穴は塞がる** — 言語を触らずに済むほうを採る。

**省略時に効いた版を別のキーで出す** (`"koyu-effective"`) 案は、ツールの既定を文書に入れることに変わりがない。バイトがツール版に依存する状態は同じである。

**照合順を JavaScript の既定 (UTF-16 コード単位順) のまま規範にする**案は、実装を一行も変えずに済む。だが別の言語で素直に書いた実装 (UTF-8 バイト比較・符号位置比較) と食い違う — **規範を実装の都合へ合わせると、参照実装が仕様になる。**この形式は「.muro のパーサを持たないプログラムへの出口」なので、他言語の側に合わせるほうが正しい。

**正規化せず、見分けのつかないキーを許す**案は、「同じ建物とは何か」の定義を編集器の入力方式と OS (macOS のファイル名は NFD) に預ける。**NFKC まで正規化する**案は書かれた表記を壊す。

**単射性を「別の種から作った模型は別のバイト」で縛る**案は、種が違っても同じ建物 (行の並びだけが違う原本) を作りうるので偽の失敗が出る。**一箇所の変更**で縛るほうが、命題として正確である。

## 帰結と代償

**形式が自分を名乗るようになった。**消費者は綴りの版で分岐でき、`format` と `koyu` のどちらを見ればよいかを迷わない。**そして「同じ入力から同じバイト」がツール版に依存しなくなった** — 版宣言の無い原本のバイトは、既定が 0.5 から動いても変わらない。

**照合順と正規化が規範になった。**別の言語で書かれた実装が同じバイト列を出せる条件が揃い、`compareCanonical` が UTF-8 バイト比較と一致することはテストが corpus で縛っている。

代償。**(1) 破壊的変更である。**`format` キーの追加と `koyu` キーの省略で、v0.15 以前の正準JSONとのバイト比較は成立しない — 保存している利用者は再生成が要る。ADR-0013 で一度払った代償を、同じ理由でもう一度払っている。**綴りを変える支払いは 1.0 の前にしかできない。**`examples/two-rooms.canonical.json` は再生成した。**(2) 照合順と正規化の変更で実際にバイトが動くのは、代用対を含む字を使った原本と、NFD で書かれた原本だけである。**同梱の全例は `format` キーの追加以外に変化が無かった。だが変わらなかったことは、決めなくてよいことを意味しない — 決めていなければ、実装を書き直した日に静かに変わる。**(3) property test の生成器が重くなった。**構文が増えるたびに生成器と `COVERAGE` を触ることになる。それは維持費だが、**母集団の狭さは緑の意味を静かに削る**ので、費用の側に置く。

三点セットで着地した: 本 ADR (なぜ) + `test/canonical-property.test.ts` (3件の property) と `test/guarantees.test.ts` (6件の規範) (保証) + [spec/canonical-json.md](../../spec/canonical-json.md) / [spec/scope.md §8・§9](../../spec/scope.md) (現在形)。
