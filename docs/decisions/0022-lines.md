# ADR-0022: 空間が名詞、線が動詞 — 位置を定めるものはすべて線である

日付: 2026-07-26 / 状態: 採用 (言語版0.5) / 起点: 特大複合建築の基壇にある「設計された斜め」と、地下の語彙

## 文脈

0.4 までの koyu は直交グリッドだけを扱った。「直交に絞る」は技術的制約ではなく**選択**だったので、選択を見直すこと自体が正当な設計行為である。特大複合建築を書き始めた途端、二種類の斜めが同時に現れた。

- **所与の斜め** — 隣地境界が折れていて、基壇の外形がそれに従う。世界から来る形で、敷地形状 polygon (ADR-0011) が既に持っている情報の帰結である。
- **設計された斜め** — 敷地を斜めに貫く通り抜け通路。**これは設計の行為であり、どこにも所与として存在しない。**

斜めへの取り組みは二度失敗している。**回転領域**は却下された (グリッド思考の延長にすぎず、設計された斜めに答えない)。**clip** も却下された — 設計された斜めから逃げており、かつ**ソースを読んでも斜めだと分からない**。二度目の失敗が本質的だった: ビルドは座標系・ジオメトリ・ソリッドの生成であって、**ソースは読んで理解できなければならない**。構成に属する事実 (斜めであること、どこからどこへ) がビルドの中に隠れるのは、記法としての敗北である。

もう一つ、通り芯オフセットという土台自体が付け焼き刃だという指摘があった。設計するとき、人はいつも通り芯から考えるわけではない。通り芯は方法の一つであって全てではないのに、記法はそれを土台と偽っていた。

## 決定

**1. 空間が名詞、線が動詞、境界はその出会い。**

- **空間** = 存在するもの。名前・用途・パスを持つ。一次要素のまま変わらない。
- **線** = 位置を実体化する行為。**位置を定めるものはすべて線**であり、出自が三種あるだけである。
  - **共有線** — 通り芯・副芯。名前を持ち、宣言一回・参照N回。
  - **所与線** — 敷地形状 polygon の各辺 (ADR-0011)。世界から来る。
  - **描画線** — 設計の行為そのもの。一つの設計判断が一行になる。
- **境界** = 二空間の関係 (位置を持たない関係文)。線はその関係の**実現**である。導出 (隣接から) が既定で、描かれたときだけ上書きされる。

**グリッドは土台から「共有線という特殊例」に降格する。**付け焼き刃感の正体は、特殊例を土台と偽っていたことだった。`grid X 0 8000 16000` は「三本の共有線に名前を付けた」という宣言であり、`space /L1/a room X1..X2 Y1..Y2` は「四本の名前付き線に囲まれた既定セル」の略記として**再解釈**される。既存の記述は一文字も変わらない。

**2. 描画線の構文は `line`。端点は通り語の対で書く。**

```
boundary /L1/mallW /L1/atrium t:200 spec:ガラスパーティション
  line X2,Y1 X2+4000,Y6
```

境界の直下に字下げして書く。**読めば斜めと分かる** — 両端のX通りとY通りがどちらも違うからである。**生の座標も角度も導入しない。**間取り生成のRLVR研究 (arXiv 2605.14117) が報告する「座標を持たせるとLLMが壊れる」知見と、通り芯が数百年運んできた抽象度の両方に従う。端点のオフセットは通り参照と同じ綴り (`X2+4000`) で、区切りはカンマである。

**3. 線は「二空間の割付の合併を、線の両側へ分け直す」操作である。**

一方が失う三角形をもう一方が得るので、**合計面積は保存される**。どちらがどちら側かは割付の面積の偏りで決まり、偏りの無い側 (線が割付をちょうど二等分する側) は相手の反対側として決まる — 「線は二つを分ける」という宣言そのものが決め手になる。両方とも偏りが無ければ分離は決まらない (LIN01)。

**片側が領域を持たない (外部) ときは、外皮を切る線になる。**持つ側だけが自分の側へ切り落とされ、相手は面積を得ない。敷地なりの隅切りはこれで書ける。

**線の及ぶ範囲は書かれた区間の外接矩形に限る。**無限直線として全体を切ると、離れた翼まで巻き添えにするからである。

**4. 形は導出される。空間は「割付」と「凸片」の二つを持つ。**

`rects` は**書かれた割付** (セル) であり、正準JSONに残る書かれた構成である。`pieces` は**導出された領域** — 凸片の集合で、既定は割付そのまま、描画線があれば半平面で切り分けた結果になる。面積・平面図・立体・敷地との照合はすべて `pieces` を読む。

**外周の壁も割付ではなく形の縁から導かれる。**切り落とされた側には壁が立たない。これは実装上いちばん見落としやすい箇所で、割付から外周を引いたままにすると「無い壁が描かれる」ことになる。

**5. 地下は宣言である。土の語彙は導入しない。**

`level B1 -5100 h:4200 slab:900 underground:1` — 地下であることは level のタグが言う。**zの負値からは推定しない**: 地盤面は敷地の事実であって、座標系の原点の事実ではないからである (敷地が傾斜していれば地上階のzが負でもありうる)。

MUN-169 が提案した「土を空間化する (`/ground`)」も「境界の属性 `soil:1`」も**採らない**。台帳の規則2がすでに答えを持っている — **物の名は spec 語彙である**。土に接する壁は `spec:RC土圧壁` と書けばよく、境界の型も新しい属性も要らない。断熱・防水・構造の要求が外気に接する壁と違うことは事実だが、それは `spec` の値が運ぶ情報であり、ツールが構造として解釈する必要はまだ生じていない。**必要になってから台帳に足す**、が語彙の育て方である。

採光については何もしない。`light` の対象は `daylight:1` を書いた室だけなので (ADR-0020)、地下は書かなければ自動的に判定の外にある。**daylight のようにルールベースで推定する必要はない。**

## 代替案

**回転領域 (却下・一度目)。** 空間に回転角を持たせる。グリッド思考の延長で、設計された斜め — 二つの空間の**あいだ**に引かれる線 — を表現できない。角度という値を導入する点でも、通り語で書くという原則を壊す。

**clip (却下・二度目)。** 空間を多角形でクリップする。ソースを読んで斜めと分からないのが致命的だった。構成に属する事実をビルドに隠す。

**線を第一級の要素にする (`line L1 X2,Y1 X2+4000,Y6` を宣言し、境界が参照する)。** 共有線の思想に忠実で、同じ線を複数の境界が参照できる。将来の拡張として正しい方向だが、今回は採らない — 実例 (特大複合建築) で同じ描画線を二つの境界が共有する場面が出なかったからである。**線の経済**の警告 (共有可能な線の命名提案) を入れるときに、あわせて第一級化する。

**制約ソルバー (「LDK20畳・南面・玄関から廊下経由」から位置を解く)。** 採らない。双方向拘束は充足不能・多解の沼である。導出はスプレッドシートと同じく**一方向・順序付き・決定的**に限り、過剰決定は check エラーにする。記法が写すのは**決定された線**までであり、決定される前の思考は写さない。この距離は正直に限界として記録する。

**敷地の辺を直接参照する (`line site.3`)。** 所与線を境界の側で可視にする筋として正しく、MUN-172 が挙げていた。今回は実装しない — 敷地の頂点を通り芯に載せれば通り語で同じ線が書けるので、実例が要求しなかった。要求が出たら足す。

## 帰結と代償

**得たもの。** 設計された斜めが、読んで斜めと分かる形で書けるようになった。特大の例の1階には貫通通路の二枚の壁が `line X2,Y1 X2+4000,Y6` として現れ、その両隣の商業区画の形は導出される。基壇の北西・北東の隅切りは所与の隣地境界に従う外皮の切り落としとして書かれる。**頂点座標は原本のどこにも無い。**

**線の経済という規律が生まれた。**描画線の本数は設計判断の数と一致すべきである。「一度斜めにしたから上階の吹抜けまで斜め」は判断ではなく惰性なので、特大の例では斜めを1階の通路だけに留め、上階の吹抜けは矩形にした。これは記法の制約ではなく、記法が可視化した設計の規律である。

**代償1: 順序に依存する。**同じ空間に複数の描画線があると、宣言順に適用される。冪等ではないので parse の出口で一度だけ呼ぶ。実用上は「線は互いに交わらない」場面がほとんどなので問題にならないが、交わる線を書けば結果は順序で変わる。

**代償2: 建築面積は割付から数える。**`site` の建築面積 (水平投影) は `rects` の合併で計算しており、隅切りぶんを引かない。出力に「粗」と明記してあるが、**線が切った形を数えていない**のは事実である。多角形の合併面積が要るので、要求が出たときに直す。

**代償3: 斜めの線の上には通り参照で開口を置けない。**斜めの線分では通り参照が一意に位置を定めないので、`at:` は 0..1 の比率でしか書けない (OPN07)。開口の位置が「線のどこか」でしか言えないのは、通り芯という共有線の恩恵が斜めでは効かないことの帰結である。

**代償4: ほぼ全辺が描画線の建物は生息域の外である。**自由曲面・自由形状の建築は書けない。**描画線の本数 = 設計判断の数、が成り立つ範囲が koyu の生息域**であり、これは制約ではなく主張である。振れた棟は「平行な描画線の族」として原理上表現できるようになったが、実例が要求するまで採否は保留する。
