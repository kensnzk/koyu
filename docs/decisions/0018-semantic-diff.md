# ADR-0018: semantic diff — 差分は構成の言葉で読める

日付: 2026-07-25 / 状態: 採用 (v0.10) / 起点: 外部レビューP1-20 ([docs/reviews/](../reviews/))、方向性計画§2.3、ADR-0014/0015の予告の履行

## 文脈

「差分は構成の言葉で読める」はこのDSLの中核主張の一つだが、実体はテキストdiffだった。author形式 (.muro) の行diffは書式・行順・コメントの変更を差分として見せ、正準JSONのテキストdiffは行順の雑音こそ消えるが、依然として行の言葉で語る — スパン展開 (`/L3..L10/A/ldk`) の一行の変更が数十行の差分に化け、空間の改名は「全削除+全追加」の洪水になる。さらにv0.10で二つの決定が意味等価な別表記を生んだ: ADR-0014は「素の宣言wall」と「省略 (既定壁)」を同じ意味・異なる正準JSONにし、ADR-0015は「uid一致・パス不一致は改名として報告する」と予告した。どちらも、意味を比べる装置が無ければ回収できない。

## 決定

**1. `semanticDiff(a, b): ModelDiff` と `renderDiff(d): string[]` を `src/diff.ts` に置く。** ModelDiffは構成の言葉の差分 — grid (通り座標の追加/削除/移動)、version/name、levels・assets・polygons、zones・spacesの追加/削除/**改名**/フィールド変化、boundariesの追加/削除/フィールド変化。renderDiffは日本語の行 (「改名 /L1/a → /L1/living (uid:sp-01)」「± 境界 /L1/a | /L1/b: t 120 → 150」) に組む。CLIは `koyu diff <a.muro> <b.muro> [--json]`、終了コードは 0=差分なし / 1=差分あり / 2=入力が壊れている (構文・合成エラー — checkの0/1と紛れない)。

**2. 比較の基底は正準表現。** 順序に意味の無い集合 (領域合併・openings・segs・areas) はtoCanonicalと同じ正準順・正準表記 (atRef??at 等) で比べる — model.tsの正準エントリ生成 (`canonicalSpaceEntry` / `canonicalBoundaryEntry` 等) を小さくexportして共有し、再実装を持たない。不変量: **toCanonical(a)===toCanonical(b) ⇒ semanticDiffは空** (テストがexamples全6エントリで検査する)。境界の向き (aキー) は正準JSONには保存されるが、edge/swing/開口が無ければ意味を持たない — その場合の入替は差分にしない。

**3. 空間・ゾーンの対応付けは2パス。** ①uid一致 (String()比較・両側消費。uidが片側で重複しているモデル — UID03エラー — では当該uidはパス照合へフォールバックし、checkエラーのモデルでも落ちない)。uid一致でパスが違えば**改名**として報告する (ADR-0015§3の履行)。②残りをパス一致。残りは追加/削除。

**4. 境界は実効集合で、安定トークンのキーで比べる。** 両モデルとも `deriveDefaultBoundaries` 適用済みの `Model.boundaries` (実効境界集合) を使い、「素の宣言wall」と「既定壁 (derived)」を同一視する — ADR-0014が生んだ表記の揺れはここで消える (素でないwall⇔derivedの対応は通常のフィールド差分として出る)。キーは対応対ごとの安定トークン (uid対ならuid、なければ新しい側のパス) 2つの昇順 + edge。空間の改名で境界が削除+追加の洪水にならない。開口は (kind, edge, at) で対にして残りを追加/削除に、segも同じ流儀 — 2段構え。polygonは巡回正規化 (回転・反転) で一致すれば差分なし、差分は頂点数と面積 (㎡・2桁) で報告する。

**5. 出力の並びは読解の順。** grid差分を先頭に置く (通りの移動が空間の面積差分の原因になる — 原因を先に言う)。空間はパス順→レベル順 (スパン展開の8行が隣接して階順に並ぶ)。

## 代替案

**正準JSONのテキストdiff (行diff)** は装置ゼロで得られるが、差分の単位が「行」であって「構成」ではない — 改名の洪水・スパン展開の増幅・素wall/省略の見かけ差分を全て利用者に残す。git diffとしては引き続き使える (排他ではない)。**author形式のCST diff** は書式の同一性まで語れるが、それはgitの仕事で、意味の差分には展開後のモデルを比べる方が短い (レビュー§11の問いへの答え: resolved側)。**編集距離ベースの対応推定** (幾何の類似で改名を推測する) は、同一性を設計判断とするADR-0015の立場と矛盾する — uidが無ければ改名は報告しない、が正しい振る舞いである。

## 帰結と代償

「二室一扉のtを変えた」は1行、「基準階の床材を変えた」は階数分の行、「部屋を改名した」は1行になる — エージェントと人間が同じ言葉でレビューできる。代償: (1) **スパン展開の冗長差分は畳まない** — 基準階8行は8行のまま出す (意味は8箇所の変化であり、束ね直しは出力層の圧縮として後日足せる — 差分の構造は変えない)。(2) **levelの改名は削除+追加になる** — levelはuidを持たない (ADR-0015はspace/zoneに限った)。必要が現れたらuidの適用範囲の拡張として別ADRで扱う。(3) 改名検出の質はuidの規律 (同じ空間に同じuidを運び続けること) に依存する — ツールは検証できない、というADR-0015の含意をdiffも継ぐ。
