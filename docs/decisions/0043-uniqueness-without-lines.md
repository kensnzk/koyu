# ADR-0043: 形は正準形の関数である (2) — 線が絡まない三つの破れを閉じる

日付: 2026-07-30 / 状態: 採用 (v0.16.0、言語版 muro 1.0) / 起点: [ADR-0041](0041-derivation-uniqueness.md) (同じ約束の一巡目) / 関連: [ADR-0040](0040-derive-reference.md) (参照実装)・[ADR-0014](0014-default-boundaries.md) (既定境界)・[ADR-0028](0028-diagnostics-per-declaration.md) (診断の並びは走査の順)・[ADR-0036](0036-machine-format-version.md) (機械形式)

## 文脈

[ADR-0041](0041-derivation-uniqueness.md) は約束1 —

```text
toCanonical(a) === toCanonical(b)  ⟹  derive(a) ≡ derive(b)
```

— を機械が縛れる述語にし、破れを四つ閉じた。四つはすべて `line` (描かれた線) が絡んでいた。**線が絡まない経路は見ていなかった。**

見ていなかった側に、三つ残っていた。いずれも `2ca4d97` で実測したもので、**`check` は緑、`npm test` の 407 件も緑のまま通る。**

### 1. 既定境界の `a`/`b` が空間の宣言順で決まる

境界を一本も書かず隣り合う二室を置き、宣言の**行を入れ替える**だけで割れた。正準JSONは両者バイト同一 (`df647bd2…`) である。

```text
a を先に書く: ref "/L1/a|/L1/b@0"  a=/L1/a  b=/L1/b
b を先に書く: ref "/L1/b|/L1/a@0"  a=/L1/b  b=/L1/a
```

宣言境界の `a` は**書かれた向き**であり、正準JSONが `a` キーとして保存するので形に持ち込んでよい ([ADR-0036](0036-machine-format-version.md))。**既定境界は正準JSONに出ない** ([ADR-0014](0014-default-boundaries.md)) ので書かれた向きが無く、`deriveDefaultBoundaries` は `[...model.spaces.values()]` の並び (= 宣言順) の `i < j` から `a`/`b` を採っていた。接触の**検出**は `[a.path, b.path].sort()` で順序に鈍感だったが、**格納する向きだけが宣言順のままだった。**

効く先は関係の同一性の綴り (`a|b@i`)・`a`/`b`・`segment.edgeOfA` の方位である。境界を書かないのは muro の定型なので、**最も普通の書き方で破れていた。**

### 2. `Form.spaces` と `slabs` の並びが宣言順である

正準JSONは `spaces` のキーをパスの照合順に並べる (`toCanonical`)。だから宣言順は捨てられる情報である。ところが `derive` の空間ループと `slabs()` は `model.spaces.values()` を回っており、**Map の挿入順 = 宣言順**を形の配列順に写していた。上と同じ最小の対で、`Form` の差は 200 行、平面 SVG も割れた。

### 3. `+` による領域の合併の書き順が形に残る

正準JSONは `at` を `sortBySerial` に通して `+` の書き順を捨てる。ところが `grids`/`rects` は書かれた順のまま保たれ、`pieces` は既定で `rects` の写しなので、**凸片・スラブ・平面のエンティティの並びが書き順の関数だった。**同梱例で再現し、`derive` の差は 293 行に達した。二片が同面積のとき、平面図の室名ラベルの座という**物理量**が「正準形が捨てた情報の関数」になる。

**約束1 は文としては書かれ、witness テストで縛られていたのに、破れていた。**縛られていたのは線が絡む三組と宣言境界だけで、[uniqueness.test.ts](../../test/uniqueness.test.ts) の同梱例の検査は**同じファイルを二度 parse** していた — それは決定性の検査であって、「正準形が同じ**別の**二ファイル」というメタモルフィックな性質は試していない。

## 決定

**捨てられた情報を読む三箇所を、正準の順に揃える。**

**1. 既定境界の `a`/`b` は正準順で決める。**`deriveDefaultBoundaries` が `compareCanonical(a.path, b.path)` で向きを決める。宣言境界の向きは触らない — あちらは書かれた向きが正準JSONに残るので、形に持ち込んでよい情報である。

**2. `canonicalSpaceOrder(model)` を立て、形が空間を読む二箇所がこれを使う。**並びはパスの照合順で、正準JSONの `spaces` のキー順と同じ規則である。使うのは `derive` の空間ループと `slabs()` の二箇所。

**`Map` の挿入順そのものは動かさない。**診断の並びは**走査の順**が契約であり ([ADR-0028](0028-diagnostics-per-declaration.md))、宣言順を必要とする読み手が別にいる。**同じモデルに二つの並びが要る** — 形は正準順、診断は宣言順。この非対称は偶然ではなく、両者が答えている問いが違うことの帰結である。

**3. 領域の綴りを parse の出口で正準順に整える。**`normalizeRegionOrder(model)` が `grids` と `rects` を同順のまま綴りの正準順へ並べ替える。**切り分け (`derivePieces`) より前に置く** — 切り分けも既定境界も `rects` を読むので、後に置けば書き順が形に残る。

**4. `canonicalBoundaryOrder` の比較を `compareCanonical` に替える。**JavaScript の `<` を使っていた。[機械形式の規範](../reference/json/index.md)が「**JavaScript の `<` と既定の `sort` はここでは使えない**」と名指しで禁じ、その理由の例として挙げている 𠮟 (U+20B9F) と 﨑 (U+FA11) そのもので、正準JSONの並びと逆順になっていた。この関数は公開面であり、`Form` の境界・開口・`seg` の添字を定義する。

## 帰結

**同梱例の `Form` が動いた。**6 例のうち 5 例のゴールデンが変わり、これが破れが実物で生きていたことの証拠である。**幾何は一つも動いていない**ことを確かめてある — 空間数・境界数・スラブ数・総面積 (0.001 ㎡ まで)・壁パネルの多重集合・スラブの多重集合・凸片の多重集合が 6 例すべてで修正前と一致する。動いたのは配列の並びと、既定境界の向きだけである。

**正準JSONのバイトは変わらない。**既定境界は正準JSONに出ず、`at` は元から `sortBySerial` を通り、`spaces` は元からキーの照合順である。だから[機械形式の版](0036-machine-format-version.md) (`koyu-canonical/1.0`) は動かない。**言語の版も動かない** — 導出物のうち正準JSONは 1 バイトも変わらず、`Form` の変化は「同じ原本から二つ出ていたものが一つになった」ことであって、意味の変更ではない。

**回帰は witness で縛った。**三つとも[uniqueness.test.ts](../../test/uniqueness.test.ts) に入れ、修正前のコードで実際に落ちることを確認した (3 件が fail、修正後は 9 件すべて pass)。

## 残っている穴

**witness は生成器ではない。**この ADR が閉じた三つも、ADR-0041 の四つも、手で書いた一組ずつである。約束1 を母集団の上で縛るには、[canonical-property.test.ts](../../test/canonical-property.test.ts) の種つき生成器に**意味保存変形** (宣言の並べ替え・`+` の入れ替え・帯と位置の書き換え) を足して、生成した対で前提と結論を確かめる形が要る。**その生成器はいま `koyu 0.5` を宣言している**ので、1.0 の語 (`over` `drop` `+ - =`) は VER04 で書けず母集団に入らない。先に版を上げる。

**機械形式の側に、この ADR が触っていない破れが二つある。**数値風のレベル名・アセット名 (`level 2` と `level 10`) が照合順に並ばない (`Object.fromEntries` が整数風キーを数値昇順で先に並べ直す)、そして通り参照の綴りが素通しするため幾何的に同一の建物が別バイトの正準形を持つ。どちらも**直せば既存のバイトが変わる**ので、`koyu-canonical` の版をどうするかを決めてからにする。
