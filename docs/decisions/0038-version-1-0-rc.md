# ADR-0038: muro 1.0 と koyu 1.0.0-rc.1 — 凍らせられる面を先に固定し、残りを名指しで残す

日付: 2026-07-27 / 状態: 採用 (v1.0.0-rc.1、言語版 muro 1.0) / 起点: [方針の総覧](../policy.md) §12・[spec/scope.md §8-9](../../spec/scope.md) / 関連: [ADR-0017](0017-language-versioning.md) (言語版の規律)・[ADR-0033](0033-attribute-tiers.md)・[ADR-0035](0035-composition-rules.md)

## 文脈

版は二本ある ([spec/scope.md §9](../../spec/scope.md))。**muro の版**は言語と意味論と合成の規則を数え、**koyu の版**は実装を数えて、どの muro を実装するかを宣言する。そして**この二本は同時に 1.0 へ到達する** — 言語の面が確定していないのに実装の面を凍結することはできず、その逆もない。

言語の側は、rc.1 の直前の三つの ADR で確定した。属性の三層と名前空間 ([ADR-0033](0033-attribute-tiers.md))、充足性の検査 ([ADR-0034](0034-sufficiency.md))、合成の六つの規則 ([ADR-0035](0035-composition-rules.md))。ADR-0035 自身が「言語に足すことは高い」という規律に照らして、`over` `drop` と字下げの `+` `-` `=` を「**1.0 で払う最後の大きな支払い**」と書いた。**払い終えたなら、版を上げなければならない。**言語版を上げずに新しい語を通すことは、ADR-0017 決定5 (言語を変える変更は版を上げる) の直接の違反である。

実装の側は、八つの面のうち六つが着地している ([docs/roadmap.md](../roadmap.md))。**だが二つは立っていない。**

- **導出規則** — 参照実装 `derive(model): Form` が無い。形はいま消費者ごとに組み立てられていて、`src/draw/plan.ts` と ugatsu の `PlanView` が同じ部品を別々に呼ぶ。**同じ部品から違う形が出る余地が構造的に残っている。**規則そのものも実装の定数にしかない (共有辺と共線マージの条件、床・天井・屋根の輪郭と z 範囲、段割りの式、壁厚の既定)
- **同一性の生成規則** — uid を機械が付与するときに何から作り、どこまで衝突しないことを保証するか

**面が確定していないのに 1.0.0 を名乗ることはできない。**1.0.0 の意味は機能の完成ではなく「壊さないと約束する面の確定」なので ([spec/scope.md §8](../../spec/scope.md))、確定していない面を抱えたまま 1.0.0 と名乗れば、その名が指すものが無い。

## 決定

**言語版を muro 1.0 に上げ、実装版を koyu 1.0.0-rc.1 とする。**

**1. muro 1.0 を切り、VER04 を切る。**`SUPPORTED_LANGUAGE_VERSIONS` に `1.0` を足し、省略時の既定を `1.0` にした。**版の新旧はこの並びの順であって綴りの辞書順ではない** — 文字列としては `"0.5" > "1.0"` なので、比較を綴りに任せれば新しい版が古い版と判定される。実装は添字で比べる。

**VER04 は「`koyu 0.5` 以前を宣言したファイルが 1.0 の語を使っている」エラーである。**1.0 で入った語は三つ — 上書き `over`、削除 `drop`、`over` 直下の集合編集 `+` `-` `=` ([ADR-0035](0035-composition-rules.md))。**旧処理系はこれらを知らない。**知らない処理系ではその行が語として読めず、上書きも削除も起きないまま**黙って別の建物になる**。これは VER03 (0.4 以前のファイルに 0.5 の語) と完全に同型の理屈であり、実装も本文もそれに倣った。旧版は意味保存の場合のみ受理される ([ADR-0017](0017-language-versioning.md) 決定3) という規律の、四つめの適用である。

**上書きの跡は合成後のモデルにも機械形式にも残らない** (合成の規則5 — `over` で `h:2400` にした模型と最初からそう書いた模型は同じ正準JSONを与える)。だから VER04 が宣言を指すには、**宣言の出所だけを別に持つ**しかない。`Model.compositionEdits` が走査の順に語と対象と行を持ち、診断以外の誰も読まない。母集団は書かれた宣言であり、出所を必ず持ち、並びは走査の順である ([ADR-0028](0028-diagnostics-per-declaration.md))。

**2. 実装版は 1.0.0-rc.1 とする。** **rc は「凍らせる用意ができた面を先に固定し、残りを名指しで残す」ための版である。**六つの面 — 合成の規則・属性の三層と名前空間・機械形式・構造整合の診断・公開 API と CLI・muro 1.0 の文法と意味論 — は確定した。残る二つ (導出規則と同一性の生成規則) は [docs/roadmap.md](../roadmap.md) が名指しで持ち、**rc の間はこの二つが動きうる。**動かないと約束するのは 1.0.0 であって rc ではない。

**3. 言語版に rc は付けない。**rc.1 が実装する言語版は `1.0` である。**言語の版は意味論の版であって、実装の成熟度ではない。**`koyu 1.0-rc` のような綴りを作れば、原本のファイルが実装の成熟度を名乗ることになり、しかも `1.0-rc` と `1.0` の受理条件をもう一本設計しなければならない。意味論が同じなら版も同じである。

**4. 版を名乗る箇所をすべて揃える。**`package.json` / `package-lock.json` の二箇所 / `CITATION.cff` / `src/mcp.ts` の `serverInfo` / spec の五文書 (日英)。`test/release.test.ts` が機械的に照合する — 版が二本あるので、**乖離は文で防げない**。

## 代替案

**0.16.0 のままにする**案は、いちばん安い。だが ADR-0035 が言語に四語を足しており、言語版を上げずにそれを通すことは ADR-0017 決定5 の違反である。しかも **VER04 が切れなくなる** — `0.5` を宣言したファイルに `over` を書いたとき、それが旧版なのか最新版なのかを言う語が無い。無音の経路を一つ新しく作ることになり、[ADR-0033](0033-attribute-tiers.md) が塞いだばかりのものを開け直す。

**1.0.0 を名乗る**案は、導出規則と同一性の生成規則が立っていない以上、**約束していない面を約束したことにする**。凍結の意味が「壊さない」である以上、確定していない面を含めて名乗れば、最初の変更でその約束を破る。1.0.0 の後に破るのは破壊的変更であり、rc の間に動かすのは予定どおりである — **この差だけが rc の存在理由である。**

**言語版も 1.0-rc にする**案は、決定3 の裏返しである。原本のファイルは意味論を名乗るのであって、処理系の出来を名乗るのではない。`koyu 1.0-rc` と書かれたファイルは、1.0.0 が出た日に何を意味するのか — 書き換えを強いるなら意味保存の受理条件が要り、強いないなら二つの綴りが同じ意味論を指して永久に並ぶ。どちらも払う理由が無い。

**VER04 を ATT03 (台帳に無い属性キー) に切る**案は、[ADR-0033](0033-attribute-tiers.md) の「帰結と代償」が予告していたものである。**採らなかった。**ATT03 の本文は既に「綴りを確かめるか、名前空間を付ける」と直し方を言っており、**そこは版を上げる話ではない**。`heigh:2400` は 0.5 でも 1.0 でも天井高にならない綴り違いであって、版を上げれば意味が変わるものではない。VER の族が言うのは「旧版と新版で**同じ文が違う意味を持つ**」ことだけであり、これはその形をしていない。二択を示せない場所に二択のコードを切れば、直し方が二つに割れて片方 (「`koyu 1.0` へ上げる」) が嘘になる。`0.5` 以前を宣言したファイルで名前空間なしの自由属性が使われていれば、**版に関わりなく ATT03 でそのまま落ちる**。ADR-0033 の当該箇所にこの相互参照を書き足した。

**rc を出さず、導出規則と同一性を先に片付けてから 1.0.0 を出す**案も筋は通る。だが言語の側は既に確定していて、**確定した面を宣言しないまま抱えることには代償がある** — examples も spec も「最新版」が何かを言えず、VER04 が切れず、利用者は何を頼ってよいか分からない。rc は、確定した面と未確定の面を**同じ版の中で区別して名乗る**ための道具である。

## 帰結と代償

**言語の面が宣言された。**`koyu 1.0` が最新版であり、examples 全15棟がそれを名乗る。`0.5` 以前のファイルは、合成の語を使っていなければそのまま通る — 使っていれば VER04 が止める。移行は一行の書き換えである。

**残りが名指しになった。**[docs/roadmap.md](../roadmap.md) の八つの面の表から 🔨 が二つに減り、その二つが 1.0.0 の唯一の条件である。**表から 🔨 が消えたときが 1.0.0 である。**

代償。**(1) rc の間、二つの面は動きうる。**`derive()` の形は決まっていないので、いま `segmentsFor` や `placeOpening` を直に呼んでいる消費者 (ugatsu を含む) は、`Form` が立った日に書き換えが要る。これは rc が明示的に留保している範囲である。**(2) 版が二本あることの費用が増えた。**muro 1.0 と koyu 1.0.0-rc.1 が同時に動いたので、どちらの版の話をしているかを文書が常に言い分けなければならない。spec/scope.md §9 がその規範であり、言語の面を持つ文書 (scope.md・composition.md) のヘッダは「koyu v1.0.0-rc.1 / muro 1.0」と二本並べて名乗る。**(3) `Model` に診断のためだけの列が増えた。**`compositionEdits` は導出も正準形も読まない。合成の規則5 (跡を残さない) と VER04 (宣言を指す) の両立には、これしか形が無い。

三点セットで着地した: 本 ADR (なぜ) + `test/composition.test.ts` の VER04 の1件と `test/release.test.ts` の版の一致 (保証) + [spec/language.md §2](../../spec/language.md) の版の規範・[spec/semantics.md](../../spec/semantics.md) の診断台帳・[guide/diagnostics.md](../../guide/diagnostics.md) の VER04 の節 (現在形)。
