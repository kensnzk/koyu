# 0030 — 柱は何かを支える所にだけ立つ (ADR-0023の改訂)

日付: 2026-07-27
状態: 採用

## 文脈

ADR-0023 は柱を「通り芯の交点のうち、床のある空間の内側」に導いた。この規則は
屋上庭園・セットバックのテラスにも柱を立てる — それらも「床のある空間」だからである。
双塔の例 (examples/twin) で、緑化テラスとB棟屋上庭園のパラペット際に柱の列が立ち、
3Dで見ると手すりの外に柱塔が並ぶ姿になった。実際の建築では、上に何も載らない
露天の床に柱は無い — 柱は上の床か屋根を支えるために在る。

## 決定

柱の敷地 (columnSites) から、**半屋外でかつ上に床が無い空間**を除く。

- 半屋外は既にある導出 (ADR-0007): 外部に対して open または air:1 の境界で接する。
- 上に床が有るかも既にある導出 (ADR-0009 の isCoveredAbove): どのレベルであれ
  平面で重なる上階の空間が有るか。

つまり「空しか支えない床には柱を立てない」。露天のテラス・屋上庭園から柱が消え、
上階が張り出しているバルコニーの下 (柱が実際に要る所) には残る。

## 棄却した代替

- **type:terrace の特別扱い** — 語彙の掟 (ADR-0020) に反する。構造として解釈する
  型は exterior / void の二語だけで、判定の入口は型ではなく属性か導出に置く。
- **columns:0 のような抑制属性の新設** — 語彙が増え、言語版が上がる。書き手に
  「柱を消す」操作を要求するが、消えるべき場所は導出で分かる事実である。
- **宣言の通り名 (X../Y..) で範囲を絞る** — テラスはL字や帯で、直積の絞りでは
  表せない。書けても、セットバックのたびに宣言を書き換える羽目になる。

## 帰結

- 書かれたテキストの意味は変わらない (語彙・構文とも不変)。変わるのは導出だけ
  なので言語版は上げない。正準JSONの columns は宣言の列であり、影響を受けない。
- 露天の床しか無いレベルに宣言が掛かると COL01 (一本も立たない) になり得る。
  これは正しい警告である — その宣言は何も支えていない。
- 検査 (COL01/COL02)・平面・軸測・門番の柱×扉判定は、この導出を通して同じ柱を見る。
