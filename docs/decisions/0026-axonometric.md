# ADR-0026: 立体もSVGで出す — 確かめる手を平面と同じにする

日付: 2026-07-26 / 状態: 採用 / 起点: 「ブラウザで3Dタブを反応させる以外の方法で3Dを確認する方法を考えたほうがいい」

## 文脈

koyu は平面図をSVGで吐く。生成して、見て、直す — この輪が短いから、平面の生成規則は速く正しくなった。壁の欠け、扉の位置、階段の切断、どれも図を見れば分かる。

立体にはこの輪が無かった。三次元は穿つ (ugatsu) がブラウザで three.js を回して初めて見えるので、確かめるには「開発サーバを立て、タブを切り替え、画面を撮る」が要る。この経路は**壊れやすい**。実際、作業中にブラウザのタブ切り替えが反応しなくなり、立体の検証だけが止まった。数値で境界や立体の座標を確かめることはできたが、**それでは「見て分かる誤り」が見つからない**。

この非対称は道具の都合であって、記法の性質ではない。**形はどちらも同じ導出から出る。**平面が「そのレベルで切った断面」の投影なら、立体は切らない投影にすぎない。ならば同じ経路で出せるはずである。

## 決定

**1. `koyu axo` が軸測図をSVGで吐く。**

等角投影で、**生成物だけ**を描く — 床と屋根 (ADR-0024)、壁 (境界から)、柱 (ADR-0023)、縦動線 (ADR-0021)。どれも原本には無く、規則から現れるものである。空間の気積は描かない (中身が見えなくなるため)。

```sh
koyu axo examples/complex/main.muro -o out/axo.svg
koyu axo examples/complex/main.muro -l B2..L6 --no-walls   # 壁を落として中を見る
koyu axo examples/complex/main.muro -d NW                  # 別の隅から
```

**2. 実行時依存は増やさない。**

WebGLもヘッドレスブラウザも使わない。等角投影は掛け算二つで、隠面処理は画家のアルゴリズム (奥から描く) と裏面の除去で足りる。**依存ゼロという制約が、かえって正しい落としどころを選ばせた** — 正確なZバッファが要る絵ではなく、確かめるための図だからである。

**3. 立体はすべて「底面の輪郭 + 頂点ごとの上端/下端z」に落とす。**

壁も柱も床も段板も、これで表せる。斜路とエスカレーターの傾いた版は、頂点ごとに上端zが違うだけである。描かれた線 (ADR-0022) による斜めの壁も、輪郭が斜めになるだけで同じ形に収まる。**一つの表現に揃うので、新しい要素が増えても描き手は増えない。**

**4. 穿つは要らなくならない。**

軸測図は静止画で、選択も断面も回転も無い。穿つが持つ対話性 (空間をクリックして隣接を見る、レベルを隠す、経路を光らせる) は別の価値である。**軸測図は開発の輪を閉じるための道具**であって、人に見せる立体の置き換えではない。

## 代替案

**ヘッドレスブラウザ (puppeteer/playwright) で穿つを撮る。** 実物と同じ絵が出るのが強い。採らなかったのは、CIと手元の両方に重い依存が増えること、そして**確かめたいのは koyu の導出であって穿つの描画ではない**からである。穿つの不具合で koyu の検証が止まる、という今回の事故がそのまま繰り返される。

**穿つ側にURLの深リンク (`#3d`) を足す。** タブの反応しない問題は直るが、依存の向き (koyu の検証がブラウザに依る) は変わらない。**これは併用すべきで、棄却ではない。**

**立面図を先に作る。** 立面のほうが図面としては正統だが、確かめたいのは階段の段・斜路の傾き・隅切りの立ち上がり・屋根の掛かりで、**どれも正投影では重なって見えない**。軸測が先である。立面は同じ投影の関数を変えるだけなので後から足せる。

**数値の検査だけで済ませる (テストで座標を固定する)。** 実際そうしていて、テストは残す。だが今回見つかった誤り — 斜めの壁が立たない、吹抜けの上が開いている、隅切りが敷地からはみ出す — は**どれも「見れば一目」で、座標を眺めても気づかなかった**。人間が指摘するまで分からなかったのが証拠である。

## 帰結と代償

**得たもの。** 立体の確認が `koyu axo ... -o x.svg` の一行になった。平面と同じ輪で回る。この決定の直後、**吹抜けの上に屋根が架かっていない**ことが図から見つかり、`slabs` の規則を直した (床の不在は屋根の不在ではない、という一行の誤り)。道具を作った回でその道具が最初の獲物を出したのは、輪の短さの効き目である。

**代償1: 隠面処理が近似である。** 立体ごとの代表点で奥から並べるだけなので、長い床版と手前の柱のように大きさの違うものが交差すると前後が入れ替わることがある。正しくするにはBSPか分割が要るが、確かめるための図にその精度は要らないと判断した。

**代償2: 開口を描かない。** 扉と窓は壁の面に穴として出ない。立面を作るときに正面から必要になるので、そこで足す。

**代償3: 空間の気積を描かない。** 用途別の色分けで塊を見る、という穿つの見せ方は再現しない。`--no-walls` で中を覗く手はあるが、それは別の図である。
