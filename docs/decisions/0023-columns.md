# ADR-0023: 柱は通り芯の交点から現れる — 点の要素にも「置く操作」を作らない

日付: 2026-07-26 / 状態: 採用 (言語版0.5) / 起点: 「建築要素が壁と床と扉と窓だけでは寂しすぎる。柱もいる」

## 文脈

koyu が持っていた建築要素は、空間・境界 (壁) ・開口 (扉と窓) ・敷地だけだった。床とスラブは level の `slab` が暗黙に与え、天井は `h` が与える。これで平面図は成立するが、**図面が薄い**。実務の図面には柱があり、柱の並びは建物の構成そのものを語る。Revit のシステムファミリに相当する要素群を揃えていく方向性の、最初の一歩として柱が要る。

問題は、柱が**点の要素**であることだった。壁は「二つの空間の境界」という関係から現れるので、壁を置く操作はどこにも無い。これが koyu の中心的な主張である。柱を同じ構えで扱えるのか、それとも「置く」しかないのか。

## 決定

**1. 柱は寸法と階と通りだけを書く。位置は書かない。**

```
column 900 B2..L6
column 800 L7..L13 x:X2,X3,X4,X5,X6,X7
```

`column <一辺mm> <レベル範囲|レベル名> [d:奥行] [x:通り,..] [y:通り,..] [自由属性]`

**位置はどこにも書かれていない。**柱は「通り芯の交点のうち、そのレベルに床のある所」に立つ、という規則で導出される。床の有無は、そのレベルの `exterior` でも `void` でもない領域つき空間の中にその点が含まれるか、で決まる。

これは壁の扱いと厳密に同型である。壁は「二つの空間が接する所」に現れ、柱は「通りが交わり、かつ床がある所」に現れる。**どちらも、既にモデルにある二つの事実の交わりである。**

**2. 通り芯は既に共有線である。柱はその帰結にすぎない。**

ADR-0022 が通り芯を「共有線」と位置づけ直したことで、この決定は自動的に正当化される。通り芯は作図の補助線ではなく**構造の骨格**であり、実際の建物で柱が通り芯に立つのは偶然ではない。記法が通り芯を持っているのなら、柱の位置はもう書かれている。`column` は「その骨格を、この階では900角で実体化せよ」と言っているだけである。

副作用として、**構造グリッドと作図グリッドが同じ一つのものになる**。これは正しい — 分けている実務の慣習は、ツールが両者を別々に持つことから来る事故である。

**3. 上へ行くほど細くなるのは、階の範囲を分けて書けば出る。**

`column 900 B2..L6` / `column 800 L7..L13` / `column 700 L14..L19` と三行書けば、断面が階で変わる。位置は変わらないので書き直しは要らない。特大複合建築の例はこの三行で21レベル分の柱を持つ。

**4. 同じ交点に二本は立たない。先の宣言が勝つ。**

「大きい方を採る」のような暗黙の規則は持たない。通りを限定しない宣言が同じレベルに複数あれば警告する (COL02) — 後から書いた寸法が黙って無視されるのを知らせるためである。宣言に対して一本も立たなければ警告する (COL01) — 階の指定違いや通りの限定の書き間違いは、これが無いと気付けない。

**5. 柱は空間でも境界でもない。面積にもグラフにも現れない。**

柱は集計に入らず、`doors` の経路にも影響しない。平面図には塗り潰しの矩形として、3Dには階高いっぱいの角柱として現れる。**第四の一次要素ではなく、通りと床という既にある事実から現れる第三の生成物**である (壁・開口に次ぐ)。

## 代替案

**柱を空間として書く (`space /L1/c1 column X2..X2+900 Y3..Y3+900`)。** 記法を一切増やさずに済むが、柱が面積に算入され、隣室との境界が導出され、`doors` のグラフに節点として入る。すべて誤りである。柱は空間ではない。

**柱の位置を書く (`column /L1 X2 Y3 900`)。** 素直だが、**「壁を置く操作は存在しない」と言いながら柱を置く**ことになる。一貫性を失うだけでなく、実用上も損である — 30階建てで通りが8×6なら、書く行数が桁で違う。位置を書けるようにすると、通り芯から外れた柱も書けるようになるが、それは「柱は通りに立つ」という構成の事実を捨てることでもある。

**床の有無を見ずに全交点に立てる。** 実装は単純になるが、外部空間・吹抜け・敷地の上に柱が生える。床の有無を見る規則は、**空間が一次要素であることの利点がそのまま効く箇所**でもある — 部材モデルなら「スラブの範囲」を別に持たなければ同じ判定ができない。

**丸柱・任意断面を導入する。** `d:` で矩形断面までは書ける。丸柱や異形断面は形の語彙であり、`spec` の値として運べば図面には出せるが、生成される形は角柱のままになる。要求が出るまで持たない。

## 帰結と代償

**得たもの。** 図面が図面らしくなった。通り芯の丸に対して柱が立つと、平面図は一気に建築の図になる。特大複合建築の基壇では8×6の通りに柱が並び、地下では柱の間に駐車区画が読める。3Dでは階を貫く柱列が構造の骨格を見せる。

**そして「置く操作を作らない」という規律が、点の要素でも守れることが示された。**壁 (線) ・柱 (点) と来たので、次の要素 (梁・小梁・スラブの段差) も同じ構えで扱えるかを問える。

**代償1: 通りから外れた柱は書けない。**独立柱・斜め柱・移柱は表現できない。基本計画の解像度では通りに立つ柱がほとんどなので当面は困らないが、**これは制約であって近似ではない**。

**代償2: 柱と他の要素の干渉を検査しない。**柱が階段の走りや扉の開口と重なっても何も言わない。エスカレーターが柱と重なっていることに人間が気付いて指摘した、というのが実際に起きたことである。干渉検査は要素が増えてから、一度にまとめて入れるべき問いである。

**代償3: 柱は境界に影響しない。**壁の中に柱があっても壁厚は変わらないし、柱型が室内に出っ張っても面積は減らない。壁芯面積という既定の解像度と整合しているが、実施設計の解像度ではない。
