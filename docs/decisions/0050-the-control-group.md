# ADR-0050: 帰無仮説の対照群 — 「それは独自 JSON Schema では?」に実験で答える

日付: 2026-07-30 / 状態: 採用 (v0.16.0、言語版 muro 1.0) / 起点: W3 (帰無仮説実験) / 関連: [ADR-0020](0020-daylight-scope-is-declared.md)・[ADR-0032](0032-three-domains.md)

## 文脈

「muro は独自の JSON Schema では?」は専門家から必ず来る問いである。理論の返し (「JSON Schema は等価性も合成も定義しない。muro は両方を定義する」) は**主張であって、反論できる。**実験は反論できない。

だから同じ建物を二通りに持たせ、同じ編集課題を同じ条件で解かせる。**負けたら言語の主張は死ぬ。それが分かること自体に価値がある。**

## 決定

**対照群は muro から機械的に書き出す。**判断基準は四つで、効く順に並べるとこうである。

1. **同じ情報を持つ。**情報量が違えば、勝ち負けは「導出があるか」ではなく「情報が足りるか」の話になる。同じ原本からの書き出しなら構成上等しい — 属性・室名・くくりまで運ぶ (`floor:オーク` は `Form` に出ないが原本には書かれている)
2. **第三者が再走行できる。**手書きの一枚は再生成できない。書き出し器はコードなので走らせ直せる
3. **藁人形と言われない。**形が不当だという批判は `export.ts` を読んで具体的に言える
4. **測りたいものだけが違う。**書き出しは muro の関係性を一つも持ち込まない — 壁は「二つの空間の境界」ではなく端点と厚みを持つ物であり、既定の壁は無く、すべて明示的に並ぶ

走行条件は **Opus 5 のみ・各3回** (ken の判断)。fixture は `tower` である。

## オラクル — `agreement` が見出しの数字である

対照群にはモデルが無いので、オラクルは JSON に対して回る。四つが共通で、一つが課題ごとである。

`schema` (構造と型) / `refs` (参照整合) / `geometry` (重なりと開口の位置) / **`agreement` (保存された導出量が幾何と合うか)** / `assert` (課題の主張)。

**`refs` と `geometry` が別に要るのは、JSON Schema がそれを言えないからである。**`pattern` は `opening.wall` が `W004` の形だと言えるが、W004 が実在するとは言えない。

そして `agreement` が実験の存在理由である。保存された面積・くくりの合計・階高は、**編集が置き去りにできる事実**である。置き去りにされたとき、文書は妥当で、参照は解け、幾何は整合し、それでも建物は自分について嘘を言っている。**JSON の側にそれを言うものが無い。**muro では同じ間違いができない — 面積を保存しないので、歩調が崩れる先が無い。

## `agreement` が意図的に問わないこと

**壁の高さが階高と一致するかは問わない。**それは muro の導出規則 (`h:` や `air:` が言わなければ壁は階高まで立つ) であって、対照群はそれを教えられていない。**知らない規則で採点するのは、この設計が避けようとした不公平そのものである。**

そして実害が即座に出た — その規則を入れたまま**未編集の**書き出しを採点すると、同梱例6例のうち4例が落ちた。`h:` を持つ壁と `air:1` の壁が**正しく**低いからである。**未編集の文書で落ちるオラクルは何も測れない。**どの走行も「壊れている」と出るだけになる。

残した三つは、文書が自分自身と合っているかだけを問う — 室の面積とその凸片、くくりの合計とその成員、階高と上のレベルまでの差。

## 主張は幾何に問わなければならない

`control.asserts` の式が `room(id).areaM2` を読めば、**保存値が古い文書でも通ってしまう** — 測りたい失敗そのものをすり抜ける。`areaOf(room(id))` を使う。`loadTask` が `.areaM2` を読む式を拒む。

## 着手して分かったこと — harness が黙って腐っていた

**`eval/score.ts` は起動すらしなかった。**公開面から `daylight` を引いていたが、[ADR-0032](0032-three-domains.md) で core と検証を分けたときに `daylightInputs` へ改名され、判定は `daylight.ratio` へ移っていた。追随していなかった。

**課題のオラクルが古い数字を主張していた。**`tower` が境界1本と窓1枚ぶん漂流しており (境界 542→543、窓 157→158、開口 286→313)、「不変」を主張するオラクルが**どの走行も満たせない数字**を持っていた。

**どちらも `npm test` に見えていなかった。**harness を import するものが一つも無かったからである。だから `test/eval-harness.test.ts` を置いた。縛るのは三つ — 全課題ファイルが読めて検証を通ること (import の腐りと `control` の書き損じ)、**fixture の不変量が課題の主張する数字と一致すること** (漂流)、そして**参照解が両条件で通ること** (課題が達成不能でないこと)。

## 測れたこと

参照解は両条件で通る。つまり課題はどちらでも達成可能で、比較は不正ではない。違うのは**同じ意味の変更の値段**である。

| | 編集 | 変更行数 | オラクル |
|---|---|---|---|
| muro | 1行 | 2 | 6/6 |
| 対照群 | 8箇所 (レベルごと) | 16 | 10/10 |

`space /L3..L10/A/ldk` は muro では一行、対照群では八つの室である。**これは書き出しの都合ではなく、「導出が無い」の意味そのものである。**

大きさの比は繰り返しの多い建物で開く (house 2.8倍 → complex 24.7倍)。**`complex` は対照群では 200K の文脈に入らない。**これは欠陥ではなく所見だが、実験を `tower` で走らせる理由である。

## 走行の規律 — 何が走行で、何が走行でないか

装置が揃った後で、走行そのものに規律が要ることが分かった。[PROTOCOL.md](../../eval/control/PROTOCOL.md) に置いた。

**被験者が答えを読めないようにするのは、指示ではなく構造でやる。**`eval/tasks/` にはオラクルと参照解があり、`eval/control/oracle.ts` には「どの保存値を検査するか」が書かれている。そして**対照群にとっては `examples/tower/*.muro` が編集中の建物の muro 原本そのもの**である。「読むな」と言うだけでは足りないので、それらを落とした worktree を作って被験者の処理系にする。残るのは指示が正当に許しているもの (`docs/reference/`・`src/`・小さな例) だけである。

**基盤の失敗は走行ではない。**API エラー・タイムアウト・容量超過はどれも課題が失敗したのではない。作業ディレクトリを捨てて作り直す。**中断されたエージェントが触ったディレクトリを採点してはならない** — 誰も選んで残していない半端な編集が入っている。

**参照解は走行ではない。**達成可能性を示すもので、課題の `notes` に書く。`records.jsonl` には入れない。

**別のモデルは測定ではない。**装置が端から端まで動くことを安いモデルで確かめるのは有用だが、`--dry-run` で走らせて記録に届かせない。

## 測定はまだ実行できていない

**装置は完成し検証も済んでいる** — 六課題すべてに両条件で通る参照解があり、prepare → 実エージェント → score の道を端から端まで通した。

**36走行は実行していない。**装置が着地した時点で Opus 5 がサブエージェントに割り当てられず、逐次でも並列でも全試行が `529 Overloaded` で落ちた。**容量で殺された走行は走行ではない**ので、記録していない。結果について現時点で分かっていることは何も無い。

W3 の受け入れ基準は「課題・採点・走行条件が文書化され、第三者が再走行できる」であり、そこには届いた。**勝敗はまだ誰も知らない。**

## 誠実さのために書いておくこと

**まともな技術者はこの JSON に整合検査器を書けるし、それで差の一部は埋まる。**それは本当で、そこが要点でもある — その検査器を書いて保つ労働が、muro が取り除いているものである。計画は対照群を「素朴な JSON + JSON Schema + validator」と定めているのでそれを測るが、この段落を [eval/control/README.md](../../eval/control/README.md) にも置いた。誰かが自分で見つけて指摘する前に、こちらから書いておく。
