# ADR-0049: 母集団に入っていなかったもの — 監査が見つけた五つの穴

日付: 2026-07-30 / 状態: 採用 (v0.16.0、言語版 muro 1.0) / 起点: [ADR-0048](0048-property-over-the-population.md) の受け入れ基準 (P1〜P5) / 関連: [ADR-0041](0041-derivation-uniqueness.md)・[ADR-0043](0043-uniqueness-without-lines.md)・[ADR-0044](0044-over-writes-what-the-declaration-writes.md)

## 文脈

[ADR-0048](0048-property-over-the-population.md) が四つの意味保存変形を母集団の上に置いた。受け入れ基準は五つの約束すべてであり、そのうち閉じたのは P1・P2・P3 と P4 の一部である。

**「残りも閉じた」と自分の読みだけで言わないために、約束ごとに独立した監査をかけた。**各監査の申し立ては別の読み手が反証を試み、生き残ったものだけを穴として数えた。

**五つ生き残った。**うち一つは私が閉じたつもりでいたもので、二つは**謳い文句が偽だった**類である。

## 決定

**九つの性質で母集団を縛る。**変形は八つ (並べ替え・逆順・端点の反転・`+` の入れ替え・帯と位置・ヘッダの並べ替え・`over` への括り出し・強度の争い) と、a/b の幾何射影である。

### 1. 線の端点の書き順 — 約束の文が名指ししているのに、母集団に無かった

[約束1](../reference/form/index.md)は「線の端点の書き順」を、形を変えてはならない情報として名指しする。生成器は毎回線を引くのに、**その向きを一度も反転していなかった** — `reverse` はブロックの中の子行の順を逆にするもので、一行の中の端点は触らない。

`canonicalizeDrawn` を入れる前のコード (`e22a5c0~1`) に受験させると seed=1 で落ちる。**「正準形は同じなのに形が違う」** — [ADR-0041](0041-derivation-uniqueness.md) が閉じた破れである。

### 2. 強度が一度も争われていなかった — 添字が逆でも全種を通る

`liftAttrsToOver` は括り出した鍵を base から**消す**。だから `over` がその属性の唯一の意見になり、**二つの層が一つの鍵を争う配置が一度も作られていなかった。**

これは「変形が空振りしている」より悪い。**強度の向きが逆の実装でも、母集団の30種すべてを通ってしまう。**実際に `prev > layer` を `prev < layer` に替えて確かめた — リポジトリ全体で落ちるのは新しく足したこの性質だけである。

閉じ方は、弱い層に元の値を残したまま強い層が別の値を書き、**強い層が勝った版**と突き合わせることである。併せて、`liftAttrsToOver` では構造上見られない三つを同じ性質に載せた。

- **層の列** (`model.layers`) — 正準JSONに `layers` の鍵は無いので、ここでしか見る道が無い
- **入れ子と二重取り込み** — 平坦化は深さ優先で、同じ層は一度しか現れない
- **`import` の順は意味である** — `over` を定義より前に置けば、黙って別の答えを出さずに言葉になる (`No such target for over`)

### 3. ヘッダが一度も動いていなかった

四つの変形はどれも `[...header, ...body]` で組む。**基盤の十宣言は不動だった。**ヘッダを本体より前に置く理由 (`grid` と `level` は使用より前、アセットは参照より前) は、ヘッダの**中**の順を凍らせる理由ではない。

族の中だけを並べ替える (`name`↔`unit`、`grid X`↔`grid Y`、三つの `level`、二つの `asset`)。`koyu` の行は先頭に、`unit` は `grid` の数値の読み方を決めるので `grid` の前に留める。

### 4. a/b の向きは、正準形の等値では縛れない

`a`/`b` を入れ替えれば**バイトは変わる** — 向きは `a` として正準形に残る ([境界](../reference/muro/boundary.md)が「正準JSONで変わるのは `a` の値だけ」と言う)。だから約束1の含意の話ではない。縛るのは**何に効いてよいか**である。効いてよいのは `edge` と[扉の開く先](../reference/muro/door.md)だけで、**幾何は効いてはならない。**

だから比べるのは形の**幾何の射影**である。落とすものが二種類あることが分かった。

- **a/b から読むと規範が言うもの** — `a` `b` `ref` `edgeOfA` `swing`
- **正準の境界順に従うもの** — [凸片](../reference/form/regions.md)が「切り分けは正準の境界順に効く」と定めるので、a/b を入れ替えれば**凸片と slab の並びは変わってよい**

面積は動かない (実測で 10.2㎡ のまま)。射影の設計そのものが、規範の二つの文の帰結である。

### 5. 縦動線が丸ごと母集団の外にあった — core 最大の部分系

生成器は `stair:` `ramp:` `escalator:` `lift:` `stack` を一つも書いていなかった。したがって **`Form.runs` は30種すべてで空**であり、`vertical.ts` (core で最も大きい単一の部分系) は性質の外にあった。`ceiling:` `daylight:` `hinge:` と境界の `type:` も同様である。

にもかかわらず、その性質の名は「the population covers the whole notation」だった。**謳い文句が偽である。**これは `+` の合併のときと同じ型の誤りで、**二度目である。**

母集団に階段・斜路・シャフト・`stack` を入れた (層範囲の空間として。grid Y を一本増やして footprint を空け、敷地の多角形を広げた)。COVERAGE に行を足し、**導出の側も痩せていないこと**を併せて縛った — 蹴上げの数・踏面・勾配はどれも原本のどこにも書かれておらず、導出だけが出す量なので、形を見なければ確かめられない。

## 途中で分かったこと

**`over` は層範囲パスに届かない。**`/L1..L2/st` は parse がレベルごとの空間へ展開するので、モデルには `/L1/st` と `/L2/st` しか無く、書かれた綴りを `over` の的にはできない。括り出しと強度の争いからは層範囲の行を外した — 展開後の綴りを当てにいくのは変形ではなく、別の建物を書くことである。

**`stack` は正準形に `stack` という鍵を持たない。**縦の境界 (`{"between":["/L1/st","/L2/st"],"a":"/L1/st","kind":"stair"}`) として出る。境界の `type:open` も `"kind":"open"` として出る。COVERAGE の行は実際の出力から書いた (推測した綴りで書けば、母集団が狭まっても緑のままになる)。

**`type:shaft` は縦の関係なので、同一レベルの二室の間に書くと VRT02 になる。**同じ階の壁の無い関係は `type:open` である。

## 開いたまま残す一件 — 凸片の並びが a/b に従う

4 を書くために射影を設計していて分かった。**a/b を入れ替えると、切り分けで生まれた凸片・slab・平面要素の並びが変わる。**幾何の値は一つも動かない (面積は 10.2㎡ のまま、線分・壁パネル・開口の位置は集合として一致し、平面要素の分類ごとの件数も一致する)。動くのは並びと、同一性の綴り (`ref`)・`edgeOfA`・振れ — 後の三つは規範が「a/b から読む」と定めたものである。

**並びは定めが無い。**[凸片](../reference/form/regions.md)は「線の切り分けは正準の境界順に効く」と言い、並びの規則は `between` の辞書順だと言う。`between` は昇順に並んだ対なので**a/b に依らない。**[約束1](../reference/form/index.md)は「空間の凸片は書かれた綴りの正準順」と言うが、これは `+` で書かれた割付の話で、**切り分けで生まれた凸片には当てはまらない。**

約束の破れではない — 約束1は正準形が等しいときだけ効き、a/b を入れ替えればバイトは変わる。だが**並びには物理的な帰結がありうる。**[ADR-0043](0043-uniqueness-without-lines.md) が閉じた破れは、面積の等しい二つの凸片で室名の座が宣言順の関数になったというものだった。同じ型の問いである。

**いま実害は観測できない。**この母集団には `seat` の平面要素が一つも出ないので (分類ごとの件数は `space/cut` 22・`run/anchor` 4 などで `seat` は 0)、座が動くところを見せられない。

したがって**閉じずに残す。**閉じるなら「切り分けで生まれた凸片も正準順に並べる」であり、それは凍る面 (導出) の意味を変えるので同梱例6例の Form ゴールデンが動く。別の ADR で決める。

## 母集団の主張には値段がある

「全構文を書く」は**主張であって、放っておけば偽になる。**この二回で偽だったのは `+` の合併と縦動線である。どちらも「書いていないことに気づく手」が生成器の側にしか無かった。

だから COVERAGE の行と `runs` の件数の検査を、主張の値段として置いた。**構文を足したら、ここに行が増えなければならない。**
