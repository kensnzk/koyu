# ADR-0042: 言語の版と実装の版を切り離す — muro 1.0 を実装する koyu 0.16.0

日付: 2026-07-28 / 状態: 採用 (v0.16.0、言語版 muro 1.0) / 起点: 1.0.0 を名乗る前の最終確認 / 関連: [ADR-0038](0038-version-1-0-rc.md) (rc.1 を切った決定 — その一部をここで覆す)・[ADR-0017](0017-language-versioning.md) (言語版の規律)

## 文脈

[ADR-0038](0038-version-1-0-rc.md) は言語版を `muro 1.0` へ上げ、実装版を `koyu 1.0.0-rc.1` とした。その文脈にはこう書かれている。

> **この二本は同時に 1.0 へ到達する** — 言語の面が確定していないのに実装の面を凍結することはできず、その逆もない。

**この一文が保たなかった。**rc.1 を切った時点で、八つの面のうち**二つが立っていなかった** (導出規則と同一性の生成規則 — ADR-0038 自身がそう名指ししている)。その二つは [ADR-0039](0039-identity-generation.md)・[ADR-0040](0040-derive-reference.md)・[ADR-0041](0041-derivation-uniqueness.md) で立った。つまり **rc.1 の時点で「同時に到達」していたのは言語の側だけ**だった。言語は本当に確定しており、実装は追いついている途中だった。

そして今、八つの面はすべて立っている。だが**立っていることと、確かめたことは違う。**1.0.0 の意味は「壊さないと約束する面の確定」であり ([scope.md §8](../../spec/scope.md))、その約束は一度したら引き返せない。MCP の実挙動・文書の現状・ugatsu の挙動・公開面の実際の中身を通しで確かめる前に名乗ることはできない。

**加えて、rc.1 は npm の上で機能しない。**npm に公開された版のうち最新は `0.15.0` であり、`dist-tags.latest` もそこを指している。`1.0.0-rc.1` は semver の**先行版** (prerelease) なので、`npm publish` しても `latest` は動かない。つまり公開しても `npm install @kensnzk/koyu` は 0.15.0 のままで、**ここまでの仕事は誰の手にも届かない。**先行版に `--tag latest` を強いる道はあるが、「不安定」と綴られた版を既定にすることになり、依存の更新機構は先行版を別扱いするので、綴りと扱いが食い違ったまま残る。

## 決定

**二本の版を切り離す。言語は `muro 1.0`、実装は `koyu 0.16.0` とする。**

**1. 二本は別の約束である。**同時に到達する必要はない。

| 版 | 何を約束するか | どこに書かれるか |
|---|---|---|
| **muro 1.0** | このように書かれたファイルは、この意味であり続ける | `.muro` の一行目 (`koyu 1.0`)・`DEFAULT_LANGUAGE_VERSION` |
| **koyu 0.16.0** | (0.x である間は何も約束しない) | `package.json`・npm |

**言語の版は意味論の版であって、実装の成熟度ではない** — これは [ADR-0038](0038-version-1-0-rc.md) 決定3 がすでに言っていたことである。ならばその逆も言える。**実装の版は実装の成熟度であって、意味論の成熟度ではない。**ADR-0038 は前半だけを採り、後半で二本を結び直していた。

`muro 1.0` はすでに出ている — 同梱例の全ファイルが一行目に `koyu 1.0` と書き、パーサの既定がそこにある。**出したものは戻せない。**一方で実装の面は、確かめるまで凍結を約束しない。0.x はまさに「まだ何も約束しない」を綴る場所である。

**2. 実装版を 0.15.0 の続きとして 0.16.0 とする。**`1.0.0-rc.1` は公開されなかったので、外から見れば存在しない版である。0.x の列に戻すことで `latest` が正しく動き、ugatsu の `^0.16.0` も素直に効く。

**3. 1.0.0 は最終確認の後に名乗る。**確認するのは、テストが緑であること**ではない** — それはすでに緑である。確認するのは**テストが縛っていない面**である。MCP の実挙動、文書が現在を語っているか、ugatsu が実際に描くもの、公開面が実際に何を出しているか。**「緑だから 1.0」ではなく「見たから 1.0」にする。**

**4. rc.1 で採用された ADR の 状態 行を `v0.16.0` に改める。**[ADR-0032](0032-three-domains.md) から [ADR-0041](0041-derivation-uniqueness.md) までの十件が「採用 (v1.0.0-rc.1)」と書いている。**決定の中身は一字も変えない。**変えるのは「どの版で採用されたか」の記録だけであり、`1.0.0-rc.1` は誰も入手できない版なので、そのままでは**存在しない版を指す記録**になる。決定は追記のみという規律は決定の本文にかかるのであって、その決定が実際に載る版の綴りにはかからない。

## 代替案

**1.0.0-rc.2 を切り、`--tag rc` で公開する。**教科書どおりの手順であり、「これが 1.0 だと思っている、確かめている最中だ」を正確に言う。**棄却する。**`npm install @kensnzk/koyu` が 0.15.0 のままになり、公開の目的である「届けること」が達成されない。rc を入手するには版を名指しするか `@rc` を書く必要があり、それを知っているのは既にこの企てを追っている人だけである。**届かない公開は公開ではない。**

**1.0.0-rc.1 のまま `--tag latest` で公開する。**届く。**棄却する。**semver の先行版は「この版は不安定である」を綴りで宣言するものなので、それを既定に据えるのは綴りと扱いの食い違いである。依存の更新機構 (renovate 等) は先行版を既定で拾わない設定が普通なので、**利用者ごとに届いたり届かなかったりする。**

**1.0.0 をいま名乗る。**八つの面はすべて立っており、テストは 398 件緑である。**棄却する。**立っていることと確かめたことは違う。特に MCP は 12 のツールを外へ出しているのに、実挙動を通しで見ていない。**凍結は引き返せないので、引き返せる側で確かめる。**

**0.16.0 にしたうえで、言語版も 0.5 へ戻す。**二本を再び結び直す道である。**棄却する。**`muro 1.0` は同梱例と既定値としてすでに出ており、戻せば `koyu 1.0` と書かれたファイルが読めなくなる。しかも [ADR-0035](0035-composition-rules.md) が足した四語 (`over` `drop` と集合編集の `+` `-` `=`) を言語版なしで通すことになり、[ADR-0017](0017-language-versioning.md) 決定5 の違反と VER04 の消滅という、ADR-0038 がすでに棄却した問題がそのまま戻る。

## 帰結と代償

**代償1: 版の綴りが二本あることが、外から見て分かりにくい。**`.muro` の一行目は `koyu 1.0` なのに、npm から入るのは `0.16.0` である。同じ「koyu」という語が二つの数を持つ。緩和は [scope.md §9](../../spec/scope.md) と本ADRの表だけで、機械照合は無い — `test/release.test.ts` は二本を**それぞれ独立に**照合しており、二本の関係そのものは縛っていない。

**代償2: ADR 十件の 状態 行が書き換わる。**git の履歴には rc.1 と書かれていた版が残るので、履歴を読む人は二つの綴りを見る。決定の本文は一字も動いていない。

**代償3: 1.0.0 までもう一手かかる。**0.16.0 を公開し、確かめ、その後 1.0.0 を公開する。利用者から見れば短期間に二つの版が出る。だが**0.16.0 は 0.x なので、その間に何が変わっても破壊的変更ではない** — それが 0.x に戻した理由そのものである。

**帰結: 公開が「届く」ものになった。**`latest` が 0.16.0 を指し、`npm install @kensnzk/koyu` でここまでの仕事が入る。ugatsu の `^0.16.0` も素直に解決する。

**帰結: 1.0.0 の意味が「確かめた」になった。**rc の下では「残りを名指しで残す」が版の意味だった。0.16.0 の下では、1.0.0 は**通しで見たあとにしか来ない**。名乗る条件が「面が立った」から「面を見た」へ動いたことが、この決定のいちばんの中身である。
