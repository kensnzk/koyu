# ADR-0017: 言語版 — 三つの版の分離と、旧版の条件つき受理

日付: 2026-07-25 / 状態: 採用 (v0.10) / 起点: 外部レビュー§5.1 ([docs/reviews/](../reviews/))、方向性計画§2.3

## 文脈

`koyu 0.1` (言語版)、パッケージ版、正準JSONの形 — 三つの版が区別されないまま混在していた (レビューD-011はその帰結)。ADR-0013でパーサは版を検査するようになったが、「版が変わるとは何か」「旧版のファイルをどう扱うか」の規範が無く、最初の意味論変更 (ADR-0014) が規範を要求した。

## 決定

**1. 三つの版を分離する。** (a) **言語版** — `.muro` の意味論の版。`koyu 0.2` と宣言され、正準JSONの `koyu` フィールドに素通しされる。(b) **ツール版** — package.jsonの版。実装とspec文書のヘッダが従う (release testが同期を守る)。(c) **正準JSONのschema版** — 独立のフィールドは持たず、ツール版で識別される (spec/canonical-json.mdヘッダが契約)。JSON内の `koyu` は言語版であってschema版ではない。

**2. ツールは単一の意味論 (最新言語版) を実装する。** 版ごとの意味論の分岐は持たない — 小ささの規律。対応する版の集合は `SUPPORTED_LANGUAGE_VERSIONS`、省略時は `DEFAULT_LANGUAGE_VERSION` (=最新) の意味論で読む。**省略はツール版を跨いで意味安定ではない** — 意味を固定したいファイルは版を書く。

**3. 旧版は意味保存の場合のみ受理する — 判定可能な条件として。** 0.1と0.2の差は既定境界 (ADR-0014) だけであり、「0.1受理条件 = 既定境界の導出が空」が機械検査できる。導出が起きる0.1ファイルはcheckエラーで二択を示す (境界を宣言する / `koyu 0.2` へ上げる)。旧版で警告だったものが新版ツールでエラーに格上げされるのは代償だが、黙った意味変更よりも厳格化が正しい。受理された0.1文書は導出が空である事が保証されるため、正準JSONの `koyu: "0.1"` 素通しも両版で意味同一になる — `koyu` 素通しの健全性はこの条件つき受理に依存する (相互参照: ADR-0014決定5)。

**4. 版宣言はbase層 (entry) でのみ・一度だけ。** gridの規律 (再宣言は同値でもエラー) に合わせる。import層での宣言もエラー — 合成順による黙った上書きを禁じる。`koyu <版>` の2トークンで、版なし・余分なトークンはエラー。

**5. 言語を変える変更は版を上げ、ADRに移行を書く。** examplesは常に最新版で書く (release testが機械検査する)。

## 代替案

**版ごとの意味論の並走** (0.1モードと0.2モードの分岐) は、研究プロトタイプの実装を二重化し小ささを失う。**無条件受理** (0.1も黙って0.2の意味論で読む) は、警告つき0.1ファイルの意味を黙って変え、しかもADR-0014が当の警告を廃止するため信号も消える — 最悪の組合せとして棄却。**省略時に旧版へ据え置き**は保守的だが、新規ファイルに定型行を強いる。**正準JSON出力時のkoyu正規化** (常に最新版へ書き換え) は「書かれた表記を保存する」(ADR-0013) に反する。**schema版フィールドの新設**は、外部保存物の長期互換が問題になった時に再訪する — 先送りをここに記録する。

## 帰結と代償

「意味保存」の定義が固定された: **導出物 (canonical/graph/stats/SVG) の不変を指し、診断の増減は含まない** (uid予約のような検査の追加は意味保存の範囲内)。移行の実測: examples 6件は全て導出ゼロ (=0.1でも0.2でも同一挙動) を確認した上で0.2宣言へ更新し、全出力のバイト一致を検証した。代償: 版の受理集合が広がるたびに「新旧の差が判定可能か」の設計が要る — それがこのADRの意図であり、判定不能な変更は破壊的変更として版を分けるしかない。
