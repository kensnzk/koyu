# ADR-0033: 属性の三層と運搬層の名前空間 — 「見ていない」と「見て問題がない」を分ける

日付: 2026-07-27 / 状態: 採用 (v0.16.0、言語版 muro 1.0) / 起点: [方針の総覧](../policy.md) §5.4・§11-5

## 文脈

ADR-0028 は解釈される属性の**値**を守った。`site:yes` は敷地の検査を丸ごと無効にし、`h:35OO` は高さ不変量を消していたので、台帳の型に合わない値をエラーにした。

**だがキーは無防備のままだった。**実測すると、一字違いで同じことが起きる。

| 書いたもの | 意図 | 実際に起きたこと | `check` |
|---|---|---|---|
| `heigh:2400` | 天井高 | 天井高にならず、HGT01 (上階への食い込み) が走らない | ✔ 緑 |
| `sit:1` | 敷地の宣言 | 敷地にならず、はみ出しの判定が丸ごと走らない | ✔ 緑 |
| `stiar:N` | 階段の宣言 | 縦動線が一つも生成されない | ✔ 緑 |
| `undergound:1` | 地下 | 地上階になる。**正準JSONにも痕跡が残らない** | ✔ 緑 |
| `nmae:居間` | 表示名 | 名前が付かない | ✔ 緑 |
| `type:open` を `kind:open` と書く | 開放境界 | **壁のまま**。通行グラフが変わる | ✔ 緑 |

最後の一行はリポジトリ自身のテスト模型で起きていた。`test/diagnostics.test.ts` の走査順の模型は `boundary /L1/b /out kind:open` と書かれていて、`boundary` が読む語は `type:` なので、その境界はずっと壁だった。**この ADR の検査が、それを見つけた。**

方針は §11-5 でこれを 1.0 の前提条件に挙げている — 「書いたものが黙って消える経路…が残っている限り、1.0 は切れない」。

塞ぐ道は一つしかない。**台帳に無いキーを拒む。**しかしそれは「語彙は開いている」という koyu の主張 (ADR-0008) を殺す。センサー値も実測も点検記録も第三者の任意属性も、原本が運べることに価値がある。

## 決定

**属性を三層に分け、運搬層に名前空間を与える。**

| 層 | 例 | core の態度 |
|---|---|---|
| **構造** | パス・型・区画・レベル・関係の相手・`kind`・`t`・`edge` | **必ず見る。**壊れていれば読まない |
| **解釈** | `h` `use` `road` `daylight` `style` `turn` `uid` `name` … | 台帳が値域を定義し、**見る** |
| **運搬** | `spec` `fire` `sound` `floor` `sill` / `acme.sensor` `bems.temp` … | **見ない。**運ぶだけ |

**1. 台帳が実装の唯一の出所になる。**`src/core/vocabulary.ts` の `ATTR_LEDGER` が要素ごとのキーと層と値域を持つ。ADR-0028 の `ATTR_RULES` はここへ吸収された。spec/vocabulary.md はこの写しである。

**2. 名前空間はドット区切りである。**`acme.sensor:23` `bems.temp:22.5` `survey.measured:1097.80`。**一つでもドットがあれば運搬層**という、それだけの規則にしてある。名前空間の中身に core は一切の意味を与えない — 分割の規則すら持たない。

**3. 台帳にも無く名前空間も持たないキーはエラーである (ATT03)。**

**4. 構造として解釈される型の二語を、綴り違いから守る。**`exterior` と `void` は型の位置に書かれるが構造である。`exteriorr` と書けば外部でなくなり、実測で延床が 16.20㎡ から 32.40㎡ へ倍増しながら緑で通った。**二語の編集距離1以内**の型を拒む — 遠い語 (`room` `yard` `ldk` `厨房`) には何も言わない。開かれた語彙を殺さずに塞ぐ形はこれしかない。

**5. `level` の台帳外キーは parse が拒む。**`Level` は `attrs` を持たないので、残ったキーは正準JSONにも痕跡を残さず消える。診断にできないので、その場のエラーにする。

## 代替案

**一律接頭辞 `x-key:value`** は単純だが、出所の区別を持たない。二つの第三者 (BEMS と測量) が同じキー名を使えば衝突し、しかも衝突したことが分からない。

**出所ごとの接頭辞 `bems:temp:22.5`** は出所を持つが、値に `:` を持ち込むので `parseAttrs` の字句規則 (最初の `:` の左がキー) を変えることになる。ドット区切りは**字句規則を一切変えずに済む** — これが決め手だった。

**名前空間を導入せず未知キーを warning に留める**案は、無音の経路を残す。`--strict` を付けない CI では何も変わらない。方針が「残っている限り 1.0 は切れない」と名指した以上、warning では条件を満たさない。

**構造二語を属性へ移す (`exterior:1` / `void:1`)** 案は筋が良い — `daylight` で同じ判断を既に下している (ADR-0020)。だが examples 全15棟と guide の全 muro ブロックの書き換えを伴い、得るものは「編集距離1の守り」と変わらない。**1.0 の後、実例が要求したときに再訪する。**

**編集距離2まで拒む**案は、`exterior` に対して `interior` が距離3、`ext` が距離5 なので実害は無いが、`void` に対して `wood`・`road` が距離2 に入る。`road` は実際に使われうる型なので採らない。

## 帰結と代償

**六つの無音の経路が塞がった。**上の表の全行がエラーになる。`check --json` は一件ずつ、行と対象パスつきで返す — 母集団は書かれた宣言である (ADR-0028 の規律)。

**運搬層が正当な状態になった。**`acme.sensor:23` と書いたとき、core が「見ていない」ことは宣言されている。宣言が無ければ、見ていないことと見て問題がないことが区別できず、その状態の「異常なし」は何も意味しない。**持てるが判定しないは正当な状態であり、それを明示することが自由の条件である。**

代償。**(1) 言語の破壊的変更である。**名前空間を持たない自由属性を書いていたファイルは落ちる。言語版を muro 1.0 へ上げ、旧版のファイルには VER04 で二択を示す。 — **この後段は実装しなかった** ([ADR-0038](0038-version-1-0-rc.md))。`0.5` 以前を宣言したファイルで名前空間なしの自由属性が使われていれば、**版に関わりなく ATT03 でそのまま落ちる**。ATT03 の本文が既に「綴りを確かめるか名前空間を付ける」と直し方を言っており、そこは版を上げる話ではないからである。VER04 は合成の語 (`over` / `drop` / 集合編集) に切った。理由は ADR-0038 の「代替案」にある。**(2) 台帳の維持費が増える。**属性を足すときは `ATTR_LEDGER` と spec/vocabulary.md の両方を触る — テストが一致を守る。**(3) `spec` / `fire` / `sound` / `floor` / `sill` を台帳へ昇格させた。**これらは core が読まない運搬層だが、名前空間なしで書ける既知キーである。「台帳に載っている = core が読む」ではなくなった — 台帳は**書いてよいキーの一覧**であって、読むキーの一覧ではない。層がその区別を持つ。

三点セットで着地した: 本 ADR (なぜ) + `test/diagnostics.test.ts` / `test/domains.test.ts` (保証) + [spec/scope.md §7](../../spec/scope.md) / [spec/vocabulary.md](../../spec/vocabulary.md) (現在形)。
