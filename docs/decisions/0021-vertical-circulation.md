# ADR-0021: 縦動線は一つの関係、装置は形の生成規則 — 階段・斜路・エスカレーター・昇降機

日付: 2026-07-26 / 状態: 採用 (言語版0.5) / 起点: 特大複合建築 (延床30,000㎡) の地下斜路と、平面図に階段が現れないこと

## 文脈

0.4 までの koyu で階段は**空間の名前でしかなかった**。`space /L1/st1 stair X1..X2 Y3..Y4` の `stair` は自由語彙で、ツールは一切解釈しない。階と階の接続は垂直境界 (`stack st1 L1..L11 type:stair`) が持ち、`doors` はそれを辿って経路を答える。ここまでは正しく動いていた。

**壊れていたのは形の側である。**平面図に階段室を描くと、ただの矩形と室名が出た。段鼻も切断線も昇り降りの矢印も無い。3Dでは天井高まで押し出された箱になった。外部避難階段は「階段という名前の部屋」として立ち上がり、どこから見ても階段に見えなかった。斜路にいたっては書く手立てすら無く、地下駐車場の車路は「駐車場という型の細長い部屋」としか書けなかった。

これは figure の問題ではない。**「形は生成物である」という主張が、最も形を要求する部位で空白になっていた**ということである。平面図が「そのレベルで切った断面」だという事実は、階段でしか可視化されない — 他の部屋はどの高さで切っても同じ形をしているからだ。階段は koyu の主張が試される唯一の場所であり、そこが空白だった。

同時に、記法を増やす方向には強い制約がある。語彙の台帳 (規則1) は「関係のトポロジーだけを言う」boundary の型を増やすのを最後の手段とし、space の型で構造として解釈するのは `exterior` と `void` の二語だけだと宣言している。ADR-0020 は判定の入口を型から属性へ移し、「属性はツールの振る舞いを名指す」という形を作った。斜路を足すのに `type:ramp` という boundary の型を増やすのは、この二つの決定に真っ向から反する。

## 決定

**1. 縦動線は一つの関係である。装置は形の生成規則の違いにすぎない。**

階段・斜路・エスカレーターは、トポロジーとしては全く同じ「レベル間を通れる」である。`doors` にとって階段と斜路の区別は無く、避難経路の計算にも区別は要らない。したがって **boundary の型は増やさない** — 縦の通行可能性は `type:stair` の一語が引き受け続ける。`stack ramp B2..L1 type:stair` は自然に読める: 「この斜路はレベル間を通れる関係である」。

違うのは形だけなので、**装置は空間の属性で宣言する**。ADR-0020 が `daylight:1` で作った形をそのまま使う。

```
space /L1/st1 stair X4..X4+2800 Y4..Y5 name:階段1 stair:N form:return
space /B1/ramp ramp X1..X4 Y1..Y1+7000 name:車路 ramp:E form:return slope:6
space /L1/es escalator X6..X6+12000 Y5+2700..Y5+5300 escalator:E
space /L1/ev1 shaft X4+2800..X4+8000 Y4..Y5 name:EVバンク1 lift:1
```

属性キーが装置を名指し、値が**領域からは導けない唯一の情報**である「上る向き」を運ぶ。`lift:` だけは向きを持たないので `1` と書く。型 (`stair` `ramp`) は従来どおり自由語彙で、集計と図面の刷り字にしか使われない — `ldk ... daylight:1` と同じ重ね方である。

**2. 形は書かない。段数も踏面も踊り場も勾配も、すべて導出される。**

書かれるのは「どこに・どれだけの大きさで・どちらへ上るか」だけである。

- 段数 = ⌈階高 ÷ 蹴上げ上限 (既定180mm)⌉。蹴上げ = 階高 ÷ 段数。
- 踏面 = 走り長 ÷ (蹴上げ数 − 1)。
- 勾配 = レベル差 ÷ 走り長。
- 折返しの中間踊り場は**残余として決まる** (決定3)。

同じ大きさの階段室が、階高に応じて違う段割りを持つ。特大の例では、B2からL19まで**5行**で書かれた一つのコアの中で、基壇の階段は37段、事務所階は24段、ホテル階は19段になる。書き分けはどこにも無い。

**3. 踊り場は残余に寄せる。ただし乗り込みは踊り場ではない。**

走り長・踏面・踊り場は一つの式で結ばれていて、書けるのは高々二つである。領域 (平面が決める) と目標踏面 (快適さの定数、既定300mm) を与えると、踊り場は残余として決まる。逆に踊り場を書けば踏面が残余になる。**設計者が握りたいのは踏面の快適さのほう**なので、既定では残余を踊り場へ寄せる。踊り場が設計量になる場合 (階段の幅以上を要求される等) は `landing:` で書き、その結果の踏面を RUN06 が検査する。

**走りは領域の縁からは始まらない。**近端 (直階段では遠端も) に階の床が幅いっぱいに残り、`entry:` (既定1100mm) がその奥行を与える。縁から段を始めると階段室の扉が段板に直接ぶつかる — これは実際に最初の実装で起きた。**この帯は踊り場ではなく階の床である**ので、部品 (RunPart) にはならず、立体でも板を持たない。踊り場は階と階の間にあるものだけを指す。

**4. 並列は実機の姿に従う (エスカレーター)。**

エスカレーターは一台の呼び幅が決まっている (既定1200mm、`lane:` で上書き)。宣言された領域の幅を呼び幅で割った台数が並び、**台ごとに走る向きが交互になる** — 上りの隣は上から降りてくる一台である。3200mm幅の宣言は「幅3.2mの巨大な一台」ではなく「1.2m×2台と両側の余白」として立ち上がる。台数は導出値なので、平面の注記に出る。

**5. 平面図は「そのレベルで切った断面」になる。**

一枚の平面に二つの走りが現れる — このレベルから**上る**走り (切断面 FL+1200mm で切れ、切断線が引かれる) と、このレベルへ**下りる**走り (下階の走りを上から見たもの)。切断より先には上る走りは描かれず、その位置から先に下りる走りが見える。UP/DN の矢印がそれぞれに付く。

折返しでは切断は一本目の走り (片側の幅) にしか掛からないので、**可視の判定は部品ごとに行う**。もう一方の幅は丸ごと下りる走りのものである。これが「同じ階段室が階ごとに違う顔をする」ことの実装であり、平面図が投影ではなく断面だという事実そのものである。

**6. 書かないが検査する。**

導出値の妥当性は診断になる。RUN06 は段の寸法 (踏面 <240mm、または 2×蹴上+踏面 が 550〜700mm の外)、RUN07 は勾配 (斜路は宣言 `slope:` の上限より急、エスカレーターは常用域 約1/1.7 から外れる) を言う。**`slope:` は書く勾配ではなく許容する勾配の上限**であり、検査のためだけに存在する。MUN-168 が求めた「書かないが検査する」の最初の実例である。

RUN08 は形とトポロジーの食い違いを言う — 縦動線の形はあるのに垂直境界が無い状態は、「図には階段が描かれるのに動線が通らない」という最も気付きにくい不整合なので警告にした。

**7. 高さ不変量からの宣言的免除を第二の種類として認める。**

ADR-0006 は `type:void` を高さ不変量 (天井高 + 上階slab ≤ 階高) の宣言的免除とした。縦動線も免除されるが、**理由が違う**。void の免除は「床の不在」、縦動線の免除は「天井が面でない」である — 階段室・斜路の天井は上の走りに沿って傾いていて、`h` を一つの数で語れない。免除の種類を語彙化するかは MUN-168 の論点だったが、**語彙は増やさない**: 免除の根拠は既にモデルにある (void 境界があるか、縦動線の宣言があるか) ので、第三の宣言を足す理由が無い。頭上高さの検査は別の問いであり、ここでは扱わない。

**8. 曲線は導入しない。螺旋は折返しの連続として書く。**

`form` は `straight` と `return` の二つだけである。真の螺旋階段・螺旋斜路は書けない。これは近似ではなく**生息域の外**であり、`form:spiral` はエラー (RUN05) で明示的に拒む — 黙って直階段になるより、書けないと言われるほうがよい。

## 代替案

**斜路を boundary の型にする (`type:ramp`)。** MUN-168 の当初の提案。トポロジーが階段と同じである以上、型を増やす意味が無い。`doors` も `passable` も同じ扱いをするので、増えた型は分岐を一つも生まない — 純粋な負債である。台帳の規則1が「増やすのは最後の手段」と言っているのは、まさにこの種の「意味の無い区別」を防ぐためである。

**装置を space の型で解釈する (`type` が `stair` なら階段の形)。** 最も自然に見えるが、ADR-0020 が型から判定を追い出した直後にそれを差し戻すことになる。`階段室` `EV機械室` `階段A` のような自由な綴りが黙って形を失う (あるいは意図せず形を得る) という、まさに ADR-0020 が潰した罠が再生する。

**段数・踏面・勾配を書けるようにする。** 「基本計画では階段の段数まで決めない」という解像度の設定と矛盾する。より重要なのは、**書けると検査できなくなる**ことである。書かれた段数は正しさの基準を失う (何と照合するのか)。導出したものだけが「導いた結果が使えるか」という問いを持てる。

**踊り場を必須の宣言にする。** 検討した (「踊り場をルールベースで生成するかどうか悩ましい」という指摘があった)。決定3のとおり、三つの量のうち書けるのは二つで、書かない一つを踊り場に選んだ。踏面のほうが設計者の意思が乗る量だからである。`landing:` を残したので、踊り場が設計量になる場面では逆向きにも使える。

**エスカレーターの台数を書かせる。** 幅と呼び幅から一意に決まるので、書けば二重宣言になり食い違いうる。導出して注記に出すほうが安全である。

## 帰結と代償

**得たもの。** 平面図が階段を階段として描くようになり、3Dが段を段として立ち上げるようになった。「形は生成物」が、最も形を要求する部位で実体を持った。特大の例 (examples/complex) では、B2からL19までの2階段+2EVが**コア5行**で書かれ、階高の違う5種類の段割りが自動的に出る。地下の車路は「B2の駐車区画からB1を経て地上まで車路を通って行けるか」「その勾配は何分の一か」に変換なしで答える — MUN-168 の完了条件である。

**代償1: 領域は矩形一つに限られる (RUN03)。** L字の階段室は書けない。走り方向と幅が一意に決まらないからである。実務のL字階段室は「階段+踊り場ホール」に分けるべき場面が多いので、当面は制約として引き受ける。

**代償2: 踊り場が階高で動く。**階高を変えると踊り場の奥行が黙って変わる。これは導出の性質そのものだが、驚きうる。`landing:` を書けば固定できる。

**代償3: 頭上高さを検査しない。**斜路の桁下や階段の踊り場上の有効高さは、形が生成されている以上は計算可能だが、実装していない。ADR-0006 が持つ先送りの列に一つ加わる。

**代償4: 螺旋が書けない。**駐車場の螺旋ランプは実務で普通に使われる。折返しの連続で近似すると平面の形が実物と違う。**これは明示的な生息域の限界である**と記録しておく。曲線を導入する日が来たら、それは「斜め」(ADR-0022) が直線で足りるかどうかの判断と同時に行うべきである。
